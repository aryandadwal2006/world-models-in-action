= 3. Representation learning before generation

This chapter covers

* Learning representations without labels
* Contrastive learning, derived and trained
* Collapse and its remedies
* Masked prediction and latent bottlenecks
* Measuring and assembling a state representation

Chapter 1 introduced the three components of a world model: an encoder that compresses observations into a state, a dynamics model that predicts how the state changes, and a planner that evaluates possible futures. Chapter 2 examined what makes a useful state. It must retain the information needed to predict what happens next, avoid carrying unnecessary detail, and distinguish situations that lead to different futures. But how do we train an encoder to meet these requirements when its input is a stream of pixels and nobody has labeled which details matter?

This chapter develops one answer: self-supervised learning, in which a model learns from training signals derived from the data itself rather than from human-provided labels. An image contains more structure than its pixel values alone suggest. Different views may depict the same underlying scene. A missing region may be predictable from its surroundings. An earlier observation may contain clues about what comes next. Each relationship provides a possible learning signal, and each encourages the encoder to retain a different kind of information.

That difference is the central idea of this chapter: a learning objective specifies what information a representation is encouraged to retain. A contrastive objective rewards features that remain consistent across selected views. Masked prediction rewards features that help reconstruct missing parts of an observation. Temporal prediction rewards features that help anticipate later observations. None of these objectives automatically guarantees a good state for a world model. The important question is not simply whether the training loss decreases, but whether the resulting representation preserves the information that prediction and planning require.

We will build and test these ideas using rendered observations from the DeepMind Control Suite (DMC)footnote:[Tunyasuvunakool, S. et al. (2020). "`dm_control: Software and tasks for continuous control.`" _Software Impacts_, 6, 100022. https://doi.org/10.1016/j.simpa.2020.100022.]. The experiments use tasks such as balancing a cart-pole and spinning a finger-controlled body. For the self-supervised experiments, the encoder receives images without the simulator’s physics-state labels. We then use the simulator’s state variables to evaluate what the learned representations retain. A separate supervised reference provides a comparison later in the chapter. These tests let us examine the representations directly instead of assuming that a successful training objective must have learned the right state.

*NOTE: Three components, three different jobs*

A *static visual encoder* maps the current image, or a fixed stack of images, to a latent vector latexmath:[z_t]. It has no memory across calls. A *recurrent wrapper* is optional: it takes the current visual latent and a previous hidden state latexmath:[h_{t-1}], then returns an updated hidden state latexmath:[h_t]. That hidden state is a learned model state, not the simulator’s physical state. A *full world model* additionally needs a transition model that predicts future state or observations conditioned on actions, and components that evaluate or plan over possible futures. The GRU wrapper and CPC experiment in this chapter do not, by themselves, implement that full system.

== 3.1 Learning a state without labels

A useful state is not simply a smaller copy of an image. It is a description that preserves the information needed to understand the situation. For a moving system, that may include positions and velocities, even when those quantities are not directly available as labels.

Let latexmath:[x] denote an observation, such as an image rendered by a simulator. An encoder latexmath:[f_\theta], parameterized by latexmath:[\theta], transforms it into a representation latexmath:[z]:

[latexmath]
++++

\boxed{z=f_\theta(x)}
\tag{3.1}
++++

We will use latexmath:[z] for the representation throughout this chapter. It is a vector of latexmath:[d] numbers, where latexmath:[d] is the latent dimension. The encoder’s job is to turn a high-dimensional observation into a form that later components of the world model can use.

But what should those numbers preserve? Chapter 2 gave us the answer at a conceptual level. A useful state must retain information that matters for predicting the future and discard information that does not. We can make that requirement concrete by separating two properties.

Sufficiency means that the representation preserves the information about the physical state that is available in the observation. If the representation loses a distinction that matters, a downstream dynamics model cannot recover it just by training harder.

Minimality means that the representation avoids carrying unnecessary information. For a cart-pole, this might mean retaining the cart’s position and the pole’s angle while ignoring irrelevant differences in brightness or background texture.

The two requirements must be considered together. An encoder that retains every pixel may preserve useful information, but it has not necessarily learned a compact state. An encoder that discards almost everything may be compact, but it can also lose the information needed to distinguish different situations.

=== 3.1.1 Aliasing: when compression loses the wrong information

Suppose two cart-pole observations look identical. In one underlying situation, the cart is moving to the left; in the other, it is moving to the right. If both observations map to the same representation latexmath:[z], a downstream model receiving only that representation cannot distinguish the two situations.

This is an example of aliasing: different underlying states become indistinguishable in the representation.

=== 3.1.2 Why not train directly on the state?

Let latexmath:[y] denote the physical quantities we want the representation to retain. In our experiments, latexmath:[y] consists of the simulator’s generalized positions followed by its generalized velocities.

If latexmath:[y] were available for every training observation, we could train an encoder to predict these quantities directly. The prediction error would provide a clear signal about which information the encoder needs to retain. In real settings, however, the exact physical state is often unavailable.

There are three difficulties with relying on labelled data alone.

Cost. Human annotations and physical measurements require effort or additional instrumentation. An agent can collect images continuously, but obtaining an exact label for every image may be expensive.

Task dependence. Labels reflect the task for which they were designed. An encoder trained to recognize objects might learn their identities while neglecting motion information needed by a dynamics model.

Availability. A deployed agent does not automatically know the exact positions and velocities of every object it observes. It receives images and whatever additional sensor readings are available to it.

Labels remain useful whenever they can be obtained. A simulator can supply its internal state, a synthetic data generator can produce targets, and demonstrations can provide training signals. These are legitimate alternatives, each with its own requirements. Self-supervised learning addresses a different opportunity: the observations themselves contain relationships that can be turned into learning signals without manually labelling every example.

____
*DEFINITION — Self-supervised learning*
____

Self-supervised learning trains a model using a target constructed from the data itself, rather than a human-provided label. The model solves a task designed to produce this target, often called a pretext task. The pretext task is a means of learning a representation; its answer is not necessarily the final goal.

Consider a simple example. Take an image, rotate it by a known amount, and ask a model to identify the rotation. We do not need a person to annotate the transformed image: we already know which rotation we applied. The transformation generates the target automatically.

This clarifies the distinction between three learning settings. In supervised learning, an externally supplied label tells the model what to predict. In classical unsupervised learning, an objective seeks structure in the inputs without using an externally supplied label or a separately constructed prediction target. In self-supervised learning, the model has a target, but the data or a transformation of the data supplies it.

The terminology varies across the literature. Some surveys treat self-supervised learning as a subset of unsupervised learning; other authors emphasize that self-supervised methods do use a supervisory signal, even though it is generated from the data. This chapter uses the more explicit distinction above. For a broader taxonomy of self-supervised methods, see Gui and colleagues’ A Survey on Self-supervised Learning: Algorithms, Applications, and Future Trends (2024).

____
*NOTE — Predicting what is missing*
____

In his ICLR 2020 keynote, Yann LeCun described self-supervision through the general idea of predicting missing information (LeCun, 2020). The missing part might be a region of an image, the future given the past, or an obscured portion of an observation. These are not the same objective, but each turns structure already present in the data into a training signal.

This idea provides a useful map of the chapter: first learn from transformations and views, then from missing visual content, and finally from temporal relationships.

=== 3.1.3 The objective determines what the encoder is rewarded for keeping

Self-supervised learning is not one algorithm. It is a family of methods that construct different training signals. Each signal rewards the encoder for retaining some information, while leaving other information optional.

Rotation prediction asks the model to identify a transformation applied to an image. It rewards features useful for recognizing that transformation. Those features need not be the features most useful for predicting a system’s future.

Contrastive learning creates two altered views of the same observation and trains their representations to identify one another. The choice of alterations matters: features that survive those transformations can help identify a positive pair, while features that vary may be treated as less useful.

Masked prediction hides part of an observation and asks the model to predict the missing content from what remains visible. It rewards information that helps reconstruction. Some of that information may describe physical state; some may describe visual details irrelevant to control.

Temporal prediction asks the model to use earlier observations to identify or predict later ones. It provides a learning signal tied to what happens over time, although success still depends on the data, the prediction task, and the model.

The central principle is therefore:

____
**> **SIDEBAR — The principle behind this chapter****
____

A representation-learning objective specifies what information the representation is rewarded for retaining. Information the objective does not require may be discarded.

Contrastive learning rewards information that helps distinguish a positive view from other views. Masked prediction rewards information that helps reconstruct hidden content. Temporal prediction rewards information that helps identify or anticipate what comes next.

The objective is not the only influence. Architecture, training data, transformations, and training budget also shape the representation. A decreasing training loss does not, by itself, establish that the learned state is useful for prediction or planning.

This principle gives us a way to evaluate methods rather than simply collect them. We can examine what their objectives encourage, then measure what their learned representations actually retain.

=== 3.1.4 Why use a benchmark rather than a toy world?

The experiments in this chapter use the DeepMind Control Suite (DMC), a collection of physics-based control tasks built on MuJoCo. The observations are rendered by the simulator rather than drawn by a custom world designed solely to demonstrate a particular learning method. The suite gives us both rendered images for training and simulator variables against which to evaluate the resulting representations.

Our experiments use three tasks, shown in Figure 3.3.

* *Cartpole balance.* A pole is hinged to a cart that moves along a track. Its evaluation state has four variables: two generalized positions and two generalized velocities.
* *Finger spin.* A planar, two-joint finger interacts with a free body that can rotate. Its evaluation state has six variables: three generalized positions and three generalized velocities.
* *Cheetah run.* A planar, legged body moves across a surface. Its evaluation state has eighteen variables: nine generalized positions and nine generalized velocities.

Cartpole balance is the main task because its small state makes results relatively easy to interpret. Finger spin provides a second task for the objective comparison in Section 3.5. Cheetah run is used in Section 3.6 to examine how the size of the representation affects a task with a higher-dimensional state.

== 3.2 Pretext tasks: supervision from structure

A pretext task turns an unlabeled observation into a training example with a known target. The target comes from a transformation or relationship in the data, so we do not need a person to annotate each example.

Rotation prediction is a simple place to begin. It lets us construct the target explicitly, derive the loss from an ordinary classification problem, and then ask the central question of this chapter: does solving the pretext task require the encoder to preserve the information a world model needs?

=== 3.2.1 Rotation prediction

Take a rendered cart-pole frame latexmath:[x]. Rotate it by a multiple of 90 degrees and ask a network to predict which rotation was applied. We use four possible rotations: zero, 90, 180, and 270 degrees.

Let latexmath:[r\in\{0,1,2,3\}] be the rotation label, where latexmath:[r] counts quarter turns, and let latexmath:[\rho_r(x)] denote the corresponding rotated image. Starting with one frame gives us four training examples:

[latexmath]
++++

\big(\rho_0(x),0\big),\quad
\big(\rho_1(x),1\big),\quad
\big(\rho_2(x),2\big),\quad
\big(\rho_3(x),3\big).
++++

The label is known because we chose the transformation. No human annotation is needed.

Our frames are square, so rotating by a quarter turn simply rearranges the pixels. We do not need to introduce padding or interpolate new pixel values. The target is therefore determined by the applied rotation, rather than by an artifact created at the image border.

Now we need a network that predicts the rotation. We already have an encoder latexmath:[f_\theta] from equation 3.1. Attach a classification head latexmath:[g_\phi], with parameters latexmath:[\phi], to map the representation to four scores:

[latexmath]
++++

a(x')=g_\phi\!\left(f_\theta(x')\right).
++++

Here latexmath:[x'] is a rotated input, and latexmath:[a_j(x')] is the score, or logit, assigned to rotation class latexmath:[j]. A logit is not yet a probability. We convert the four scores into probabilities using softmax:

[latexmath]
++++

\frac{\exp(a_j(x'))}
{\sum_{m=0}^{3}\exp(a_m(x'))}.
++++

The four probabilities are nonnegative and sum to one. The model’s task is to assign a high probability to the rotation that was actually applied.

How should we measure whether it does so? Suppose the correct label is latexmath:[r]. Its predicted probability is latexmath:[p_{\theta,\phi}(r\mid x')]. We penalize the network using the negative logarithm of that probability:

[latexmath]
++++

-\log p_{\theta,\phi}(r\mid x').
++++

This is the familiar cross-entropy loss for a classification problem with one correct class. If the model assigns probability one to the correct answer, the loss is zero. If it assigns a very small probability to the correct answer, the loss is large.

We average this loss over the four rotations of each original frame, then over the training frames. The result is the rotation-prediction objective:

[latexmath]
++++

-\mathbb{E}_{x}
\left[
\frac{1}{4}
\sum_{r=0}^{3}
\log p_{\theta,\phi}
\left(r\mid \rho_r(x)\right)
\right]
\tag{3.2}
++++

The expectation averages over the training observations. The parameters latexmath:[\theta] and latexmath:[\phi] are learned together: the encoder must produce features that help the classification head identify the rotation.

A useful reference point is uniform prediction. If the model assigns probability latexmath:[1/4] to every rotation, the loss for each example is

[latexmath]
++++

-\log\frac14=\log 4\approx 1.386.
++++

The value is measured in nats, because we use the natural logarithm. A model that predicts the correct class confidently can achieve a lower loss.

Notice what we have done. We have not supplied the physics state latexmath:[y], the cart position, or the pole angle as a training label. The objective only asks the model to identify the applied rotation. Equation 3.2 is an ordinary four-class classification loss; the special feature is how its labels are generated.

=== 3.2.2 Two other pretext tasks

Rotation prediction is one example of using structure in the input to create a target. Two other classic tasks take a different approach.

Jigsaw prediction divides an image into a grid of tiles, shuffles them using a permutation selected from a predefined set, and trains the model to identify that permutation. The spatial relationships between tiles supply the learning signal. This can encourage features that capture local appearance and spatial arrangement, but it does not directly require the model to preserve physical variables such as velocity.

Colorization takes a grayscale image and trains a model to predict its color channels. The target is derived from the original image, so human labeling is unnecessary. Predicting color can encourage the model to use contextual information, but good color reconstruction is not the same as learning a state suitable for control. The objective rewards information useful for recovering color; it does not explicitly require every geometric or dynamical distinction that a downstream world model may need.

=== 3.2.3 Why a correct pretext answer may still be the wrong goal

Return to the principle from Section 3.1: the training objective determines what information the representation is required to keep. Rotation prediction rewards features that help identify the rotation label. If the scene layout or background already makes that label easy to infer, the objective may be solvable without preserving the pole angle with the precision that control requires.

The same distinction applies to the other tasks. Jigsaw prediction rewards information useful for identifying tile arrangement. Colorization rewards information useful for predicting colors. Each objective can encourage useful features, and a trained encoder may retain more information than strictly necessary to solve its pretext task. But none of these losses, by itself, guarantees that the representation is sufficient for predicting the physical future.

That is the limitation we need to solve. Rather than ask the encoder to predict one fixed transformation, we want a learning signal that encourages it to ignore irrelevant changes while preserving the distinctions that matter. Small shifts or brightness changes might be nuisance variation; different physical situations should not be made indistinguishable merely because their images look similar.

This leads to instance discrimination, the starting point for contrastive learning. We will make two altered views of an observation and ask the model to recognize them as views of the same source. The choice of alterations will matter: it defines which changes the objective encourages the encoder to ignore. In the next section, we will build this idea from first principles and derive the loss that implements it.

== 3.3 Contrastive learning from first principles

Section 3.2 showed how to manufacture a training target by transforming an observation. But the target determines what the encoder is asked to learn, and recognizing a rotation does not necessarily require a useful physical state.

Contrastive learning changes the question. Instead of asking which transformation was applied, it asks which observations came from the same source. We take two altered views of one frame and train a model to identify them as a pair among other views.

The idea is simple. Making two views agree encourages the encoder to retain information shared by both. Making it distinguish them from other views encourages the encoder to retain information that identifies the source. The mathematics turns this idea into a classification loss.

=== 3.3.1 Views, positives, and negatives

A view of an observation latexmath:[x] is an altered copy of it. Write the view as

[latexmath]
++++

\tilde{x}=t(x),
++++

where latexmath:[t] is a randomly selected transformation. The transformation is applied to the image, not to the underlying physical system.

In this chapter, the view pipeline uses two kinds of alteration. It shifts the image by a random integer offset of up to three pixels in each direction, then applies random brightness and contrast changes. The brightness offset is sampled from latexmath:[[-0.1,0.1]], and the contrast factor from $[0.9,1.1]. The values are clipped to the valid image range.

These changes are deliberately modest. They alter pixel values and image alignment, but they are intended to leave the physical situation unchanged.

A positive pair consists of two independently transformed views of the same frame. A negative pair consists of views from different source frames. The distinction comes from how we created the data, so no human label is needed.

The training process operates on a batch of latexmath:[N] source frames. Each source frame produces two views, giving latexmath:[2N] images. The encoder maps these images to representations latexmath:[z_1,\ldots,z_{2N}].

For a particular view latexmath:[i], call it the anchor. Its positive, written latexmath:[i^+], is the other view of the same original frame. The remaining views are its negatives. Excluding the anchor itself, there are latexmath:[2N-1] candidates: one positive and latexmath:[2N-2] negatives.

Thus,

[latexmath]
++++

K=2N-2,
++++

where latexmath:[K] is the number of negatives for each anchor. For example, a batch of latexmath:[N=3] frames produces six views. Each anchor has one positive and four negatives.

The transformation latexmath:[t] is a design decision, not a cosmetic detail. If the encoder must identify two views of the same frame, changes introduced randomly by latexmath:[t] cannot reliably identify the source. The encoder is therefore encouraged to become insensitive to those changes.

This is the intended benefit of the augmentation pipeline. If brightness changes do not alter the physical state, the representation should ideally remain useful despite them. But the same reasoning also creates a risk: if the transformation changes something important, the objective may reward the encoder for ignoring it.

A shift of a few pixels may be harmless for a cart-pole. A shift large enough to move the cart or pole out of view could erase information needed to estimate the state. The positive-pair definition therefore specifies which changes should be treated as irrelevant. The following equations show how the loss enforces this requirement.

=== 3.3.2 From similarity to a loss

We now need a numerical measure of how well two representations match. We will build the objective in three steps: define a similarity score, turn the candidate views into a classification problem, and minimize the classification error.

==== Step 1: Measure similarity

We use cosine similarity. For two nonzero vectors latexmath:[u] and latexmath:[v], it is the cosine of the angle between them:

[latexmath]
++++

\operatorname{sim}(u,v)=
\frac{u^\top v}{\lVert u\rVert_2\lVert v\rVert_2}.
\tag{3.3}
++++

Cosine similarity lies between latexmath:[-1] and latexmath:[1]. A value near latexmath:[1] means the vectors point in similar directions; a value near latexmath:[-1] means they point in opposite directions. A value near zero means they are approximately orthogonal.

The normalization in the denominator means that the score depends on direction rather than vector length. Simply multiplying a representation by a positive constant cannot increase its cosine similarity with another vector.

==== Step 2: Turn similarity into a classification problem

Fix an anchor latexmath:[i]. There are latexmath:[2N-1] candidate views, excluding the anchor itself. We want a classifier to assign the highest probability to the positive latexmath:[i^+].

For each candidate latexmath:[j], divide the similarity by a positive temperature latexmath:[\tau], then apply softmax across the candidates:

[latexmath]
++++

p_i(j)=
\frac{
\exp\big(\operatorname{sim}(z_i,z_j)/\tau\big)
}{
\displaystyle\sum_{k\ne i}
\exp\big(\operatorname{sim}(z_i,z_k)/\tau\big)
},
\qquad j\ne i.
\tag{3.4}
++++

Here, latexmath:[p_i(j)] is the probability assigned to candidate latexmath:[j] being the other view of the anchor’s source frame. The correct answer is latexmath:[i^+].

The temperature latexmath:[\tau] controls how sharply differences in similarity affect the probabilities. A smaller temperature magnifies differences between candidates. A larger temperature makes their probabilities more uniform.

==== Step 3: Penalize a wrong answer

We use the negative logarithm of the probability assigned to the positive. The loss for anchor latexmath:[i] is

[latexmath]
++++

\ell_i=-\log p_i(i^+).
++++

A correct answer assigned high probability receives a small loss. A positive assigned low probability receives a large loss. Averaging across all latexmath:[2N] anchors gives the normalized temperature-scaled cross-entropy loss, or NT-Xent:

[latexmath]
++++

\frac{1}{2N}
\sum_{i=1}^{2N}-\log p_i(i^+)
\tag{3.5}
++++

This is the same basic cross-entropy as in equation 3.2, but the classification problem is different. Rotation prediction chooses among four transformations. NT-Xent chooses among the other views in the batch, with a different correct class for each anchor.

Consider a batch with latexmath:[N=2], so there are four views. Each anchor has three candidate views. Suppose an anchor has cosine similarities of latexmath:[0.80] with its positive and latexmath:[0.10] and latexmath:[-0.30] with the two negatives. Let the temperature be latexmath:[\tau=0.5].

Dividing the similarities by the temperature gives logits of latexmath:[1.6], latexmath:[0.2], and latexmath:[-0.6]. Their exponentials are approximately latexmath:[4.953], latexmath:[1.221], and latexmath:[0.549]. The sum is latexmath:[6.723], so the softmax assigns probabilities of approximately latexmath:[0.737], latexmath:[0.182], and latexmath:[0.082].

The positive has probability latexmath:[0.737], giving the anchor a loss of

[latexmath]
++++

-\log(0.737)\approx0.306.
++++

If the classifier cannot distinguish the positive and assigns the same probability to all three candidates, it assigns probability latexmath:[1/3] to the positive and has loss

[latexmath]
++++

-\log(1/3)=\log3\approx1.099.
++++

For general batch size latexmath:[N], an exactly uniform probability distribution over the candidates gives loss latexmath:[\log(2N-1)]. This is the uninformative reference value for this classification problem.

____
*WARNING — Comparing NT-Xent losses*
____

Compare NT-Xent loss values only when the batch size and temperature are the same. The number of candidate views changes with batch size, and the temperature changes the softmax probabilities. A lower numerical loss under a different configuration does not necessarily mean a better representation.

____
*TIP — Batch size controls the negatives*
____

Batch size sets the number of negatives: latexmath:[K=2N-2]. A larger batch asks the model to distinguish the positive from more candidates, but it also requires memory for more views and their similarity scores.

=== 3.3.3 What InfoNCE actually optimizes

NT-Xent is one instance of the broader InfoNCE objective, used in contrastive predictive coding (van den Oord et al., 2018) and closely related to the contrastive formulation used by SimCLR (Chen et al., 2020). For each anchor, InfoNCE compares one positive with latexmath:[K] negatives. Its mathematical properties help explain both what contrastive learning encourages and what it cannot guarantee.

First, we need a measure of shared information.

____
*DEFINITION — Mutual information*
____

The mutual information latexmath:[I(a;b)] between random variables latexmath:[a] and latexmath:[b] measures how much knowing one reduces uncertainty about the other. It is the expected log ratio between their joint distribution and the product of their marginal distributions:

[latexmath]
++++

I(a;b)=
\mathbb{E}_{p(a,b)}
\left[
\log\frac{p(a,b)}{p(a)p(b)}
\right].
++++

Mutual information is zero when latexmath:[a] and latexmath:[b] are independent. With natural logarithms, it is measured in nats.

Let latexmath:[a] and latexmath:[b] be the representations of two views of the same frame. This is the positive pair. Let latexmath:[b_1,\ldots,b_K] be representations of negative views drawn independently from the marginal distribution of latexmath:[b]. For a positive score function (flatexmath:[a,b]), InfoNCE is

[latexmath]
++++

-\mathbb{E}
\left[
\log
\frac{f(a,b)}
{f(a,b)+\sum_{k=1}^{K}f(a,b_k)}
\right].
++++

For NT-Xent, the score uses exponentiated cosine similarity divided by temperature. Under the standard sampling assumptions, InfoNCE satisfies the lower bound

[latexmath]
++++

\boxed{
I(a;b)
\ge
\log(K+1)-\mathcal{L}_{\mathrm{InfoNCE}}
}
\tag{3.6}
++++

This is a result about the information shared by the two views’ representations, not a direct guarantee that the representation captures the physical state.

*Proof note.* The mutual-information lower bound follows from the Bayes-optimal classifier over one positive and latexmath:[K] marginal negatives. Appendix A gives the complete change-of-measure argument; here we use the bound only as an interpretation of shared view information, not as a guarantee that physical state is retained.

Equation 3.6 has two useful implications. First, lowering the InfoNCE loss raises the conventional lower bound on the information shared by the positive pair. Second, the bound is capped by latexmath:[\log(K+1)], because the loss cannot be negative. A finite batch therefore limits how much shared information this objective can certify.

The assumptions matter. In the chapter’s implementation, the negatives come from other frames in a batch, and two views from the same source frame are themselves related. Frames drawn from trajectories may also be correlated. The textbook mutual-information bound is therefore a useful interpretation of the objective, not an exact measurement of the trained model’s mutual information.

The deeper limitation follows from how the views are constructed. Each view is a randomly transformed copy of the same source frame latexmath:[x]. If latexmath:[z_1] and latexmath:[z_2] are their representations, the data-processing inequality gives

[latexmath]
++++

I(z_1;z_2)
\le
I(\tilde{x}_1;\tilde{x}_2)
\le
I(x;\tilde{x}_1).
++++

The information shared by both views is constrained by what survives the transformations. A detail that changes independently between views cannot reliably identify a positive pair. Conversely, information preserved across both views can help.

But shared information is not the same as the information needed by a world model. The objective asks the encoder to distinguish one frame’s views from other frames’ views. It does not explicitly ask it to preserve every state variable useful for prediction or planning.

The gradient in equation 3.7 separates attraction toward the positive from repulsion by negatives. The coefficient of each negative is its current softmax probability, so hard negatives receive more weight. Appendix A derives the gradient and the cosine-similarity derivative step by step.

[latexmath]
++++

\boxed{
\begin{aligned}
\nabla_{z_i}\ell_i
={}&
-\frac{1-p_i(i^+)}{\tau}
\nabla_{z_i}\operatorname{sim}(z_i,z_{i^+})\\
&+
\sum_{k\notin{i,i^+}}
\frac{p_i(k)}{\tau}
\nabla_{z_i}\operatorname{sim}(z_i,z_k).
\end{aligned}
}
\tag{3.7}
++++

The first term attracts the anchor toward its positive. The second term pushes it away from the negatives, weighted by their current probabilities.

Four observations follow.

Balanced forces: the sum of the negative probabilities is latexmath:[1-p_i(i^+)], so the total negative weight equals the attraction weight for this anchor.

Self-limiting updates: when the positive already receives probability close to one, both attraction and repulsion become small.

Hard negatives matter most: a negative with high similarity receives a larger probability and a stronger push.

Temperature changes the emphasis: lowering latexmath:[\tau] makes the probability distribution more concentrated, increasing the relative influence of the most competitive negative.

In the numerical example above, the attraction weight is latexmath:[(1-0.737)/0.5\approx0.527]. The two negative weights are latexmath:[0.182/0.5=0.364] and latexmath:[0.082/0.5=0.164]. Their sum is approximately equal to the attraction weight, with the small discrepancy due to rounding. Gradient descent applies the update in the opposite direction of the gradient, increasing similarity to the positive and decreasing similarity to negatives.

equation 3.7 describes the anchor’s role in one loss. The same representation also serves as a candidate in the losses of other anchors; those additional terms contribute to its complete gradient.

The key limitation remains: these gradients arrange the representations to solve the specified identification problem. The objective does not know whether the features used for identification are cart position, pole angle, texture, or some combination. That is why the following experiments evaluate the encoder rather than treating a falling loss as proof of a useful state.

=== 3.3.4 Training a contrastive encoder

We now train the loss on rendered frames from cartpole_balance. The model has two parts: a convolutional encoder that produces the representation used later, and a projection head used during contrastive training.

The encoder in worldmodels/models/encoders.py contains four convolutional layers with latexmath:[4\times4] kernels and stride two. Starting with 64 × 64 RGB input, the spatial resolution is reduced as follows:

[latexmath]
++++

64\rightarrow32\rightarrow16\rightarrow8\rightarrow4.
++++

The channel count grows from 32 to 64, 128, and 256. The final 256 × 4 × 4 feature map is flattened and projected to a 16-dimensional vector latexmath:[z=f_\theta(x)].

Source: worldmodels/models/encoders.py. This excerpt is condensed from the canonical implementation, with the architecture and behavior unchanged.

class ConvEncoder(nn.Module):
    def __init__(
        self,
        in_channels: int = 3,
        latent_dim: int = 16,
        base_channels: int = 32,
    ) -> None:
        super().__init__()
        self.in_channels = in_channels
        self.latent_dim = latent_dim
        self.conv_net = nn.Sequential(
            nn.Conv2d(in_channels, base_channels, 4, 2, 1),
            nn.ReLU(inplace=True),
            nn.Conv2d(base_channels, base_channels * 2, 4, 2, 1),
            nn.ReLU(inplace=True),
            nn.Conv2d(base_channels * 2, base_channels * 4, 4, 2, 1),
            nn.ReLU(inplace=True),
            nn.Conv2d(base_channels * 4, base_channels * 8, 4, 2, 1),
            nn.ReLU(inplace=True),
        )
        flat_dim = (base_channels * 8) * 4 * 4
        self.fc = nn.Linear(flat_dim, latent_dim)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        if x.ndim != 4:
            raise ValueError("ConvEncoder expects input shaped (B, C, H, W)")
        features = self.conv_net(x)
        return self.fc(torch.flatten(features, start_dim=1))

class ProjectionHead(nn.Module):
    def __init__(self, in_dim: int = 16, hidden_dim: int = 64, out_dim: int = 16) -> None:
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden_dim),
            nn.ReLU(inplace=True),
            nn.Linear(hidden_dim, out_dim),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x)
----

A Each convolution halves the spatial height and width.

B Maps the flattened feature map to the 16-dimensional representation.

C Maps the representation to the projection used by the contrastive loss.

With the default channel count, the encoder has 755,696 parameters and the projection head has 2,128. The encoder uses no batch normalization, so the representation of one frame does not depend on the other images in its batch.

The loss is applied to the projection latexmath:[p=g_\phi(z)], not directly to latexmath:[z]. This follows the design used in SimCLR, where a nonlinear projection head is used during contrastive pretraining while the representation before that head is retained for downstream tasks (Chen et al., 2020). The reason for separating the two is practical: the projection can become invariant to some details needed by later tasks, while the encoder representation remains available to downstream components. This chapter adopts that setup without claiming that the two alternatives have been compared experimentally here.

Source: worldmodels/losses/ntxent.py, the canonical implementation.

def nt_xent_loss(z1, z2, temperature=0.5):
    n = z1.shape[0]
    device = z1.device
    z1 = F.normalize(z1, dim=1)                         #A
    z2 = F.normalize(z2, dim=1)
    reps = torch.cat([z1, z2], dim=0)                  #B
    logits = torch.matmul(reps, reps.T) / temperature #C
    eye = torch.eye(2 * n, dtype=torch.bool, device=device)
    logits = logits.masked_fill(eye, -1e9)             #D
    labels = torch.cat([
        torch.arange(n, 2 * n, device=device),          #E
        torch.arange(0, n, device=device),
    ])
    return F.cross_entropy(logits, labels)              #F
----

A Normalizes each representation so its dot product becomes cosine similarity.

B Concatenates the two views into one batch of latexmath:[2N] vectors.

C Computes all pairwise similarities, scaled by the temperature.

D Removes self-similarity from each anchor’s candidate set.

E Identifies the positive row for each view.

F Applies cross-entropy to the positive labels, implementing equation 3.5.

Masking the diagonal excludes the anchor itself from the softmax denominator. The label indices identify the other view of the same frame: the positive of row latexmath:[i] is row latexmath:[i+N], and the positive of row latexmath:[i+N] is row latexmath:[i].

It is a verification script, rather than a second implementation intended for the main training run.

=== 3.3.5 Reading the state back with a linear probe

The simulator provides the physical state associated with each rendered frame. That state never enters the self-supervised loss. We can use it after training to ask which physical quantities are available in the representation.

A linear probe is a simple evaluation model fitted to a frozen encoder. We compute the representation latexmath:[z], freeze the encoder, and fit a linear map from latexmath:[z] to the evaluation targets. We then evaluate that map on held-out observations. This measures the information that a linear readout can recover; it does not test whether an arbitrary nonlinear decoder could recover more.

For cart-pole balance, the raw state contains four variables: cart position, pole angle, cart velocity, and pole angular velocity. The pole angle needs special treatment. The simulator stores its hinge angle as an unwrapped value, so angles separated by a full revolution can have different numbers but represent the same physical orientation. An angle of latexmath:[0.1] radians and one of latexmath:[0.1+2\pi] radians produce the same orientation.

To make a linear probe appropriate for this variable, the evaluation targets replace the angle latexmath:[\theta] with latexmath:[\sin\theta] and latexmath:[\cos\theta]. The transformed target therefore has five components: cart position, latexmath:[\sin\theta], latexmath:[\cos\theta], cart velocity, and pole angular velocity. The probe reconstructs an angle using the inverse tangent, and the repository scores angle predictions with a circular latexmath:[R^2]-like metric. This avoids treating a prediction across the angular wrap boundary as a large error simply because the numerical angle differs by nearly latexmath:[2\pi].

Let latexmath:[\check z_n] be a representation standardized using the training-set feature means and standard deviations, and let latexmath:[\tilde y_n] be the transformed target vector. The probe fits a ridge-regression readout:

[latexmath]
++++

\boxed{
\min_{W,b}
\sum_{n=1}^{M}
\left\lVert
\tilde y_n-W\check z_n-b
\right\rVert_2^2
+
\alpha\lVert W\rVert_F^2
}
\tag{3.8}
++++

Here, latexmath:[M] is the number of training examples used to fit the probe; latexmath:[W] and latexmath:[b] are the linear weights and bias; and latexmath:[\alpha] controls the ridge penalty. The current probe implementation uses latexmath:[\alpha=10^{-3}], standardizes the frozen features, and solves the ridge problem by least squares. The encoder is not updated when the probe is fitted.

Source: worldmodels/eval/probes.py, the canonical LinearProbe implementation.

[#ch3-listing-L06,reftext={chapter}.{counter:listing},caption='{listing-caption}.{counter:listing-number} ']
.Fitting a ridge probe to frozen features

[source,python]
----
def fit(self, x, y):
    x_scaled = self._fit_feature_scaler(x)             #A
    n, d = x_scaled.shape
    x_bias = np.concatenate(
        [x_scaled, np.ones((n, 1))], axis=1
    )                                                  #B
    reg = np.zeros((d + 1, d + 1))
    reg[:d, :d] = np.sqrt(self.alpha) * np.eye(d)      #C
    augmented_x = np.vstack([x_bias, reg])
    augmented_y = np.vstack([
        y, np.zeros((d + 1, y.shape[1]))
    ])
    self.weights, *_ = np.linalg.lstsq(
        augmented_x, augmented_y, rcond=None
    )                                                  #D
    return self
----

A Standardizes features with statistics from the probe’s training data.

B Adds a bias column, which is not penalized.

C Adds the rows that implement the ridge penalty.

D Solves the augmented least-squares problem corresponding to equation 3.8.

The score is computed on held-out validation frames. For ordinary state variables, latexmath:[R^2=1] is perfect prediction, latexmath:[R^2=0] matches the constant-mean baseline, and a negative value is worse than that baseline. Angular targets use the circular score described above.

A probe’s limitations are important. A high score means the physical variable is available to a linear readout. A low or negative score does not prove the information is absent from latexmath:[z]; it may be represented nonlinearly, or the probe may be limited by the data and fitting setup. The measurement tells us what is explicitly and linearly available under this evaluation, not everything the encoder may know.

The main contrastive training run and this aliasing diagnostic also use different training budgets, so their results should not be treated as a controlled comparison with all other factors held fixed. In both cases, the probes use state labels only for evaluation. The contrastive objective itself still sees rendered frames and generated view pairs.

The larger lesson is the one that motivated this chapter. The encoder is optimized for the task stated by its loss. NT-Xent rewards representations that distinguish a frame’s augmented views from views of other frames. That can organize representations and make source identity more accessible, but the loss does not explicitly require the physical state needed by a world model. To learn that state, the objective and the information available to the encoder matter.

The next section examines a failure that can occur even before asking which physical variables are represented: collapse, in which different inputs map to nearly identical representations and the model satisfies a similarity objective without learning a useful distinction.

== 3.4 The collapse problem and how it is avoided

=== 3.4.1 Demonstrating collapse

Consider the simplest possible objective for two views of each frame: make their representations equal. Let latexmath:[p_n^{(1)}] and latexmath:[p_n^{(2)}] denote the vectors compared by the loss for the two views of frame latexmath:[n]. For a batch of latexmath:[N] frames and representations of dimension latexmath:[d], define

[latexmath]
++++

\frac{1}{Nd}
\sum_{n=1}^{N}
\left\lVert p_n^{(1)}-p_n^{(2)}\right\rVert_2^2.
++++

This objective is nonnegative. It reaches zero whenever the two views produce identical representations.

But it does not require different frames to produce different representations. Suppose the encoder returns the same constant vector for every input. Then every positive pair matches exactly, the loss is zero, and the objective has reached its global minimum. The solution works regardless of what the images contain. It does not need to represent cart position, pole angle, or any other aspect of the physical state.

This is complete collapse. All inputs map to one point.

There is also dimensional collapse. Here, the representation still varies across inputs, but its variation is restricted to only a few of the available dimensions. The encoder may produce a 32-dimensional vector while using only a small number of independent directions to distinguish observations.
These are different failure modes. We therefore need more than one measurement to diagnose them.

==== Measuring collapse

The first measurement is spread: the standard deviation of each coordinate across a collection of representations, averaged over all latexmath:[d] coordinates. If the encoder returns a constant vector for every input, the spread is zero. If its outputs become almost identical, the spread approaches zero.

Spread alone is not enough, however. A representation can use many independent directions while all its coordinates have very small values. Conversely, a representation can have large coordinate variation but vary mainly along one direction.

The second measurement is effective rank, which summarizes how many directions carry substantial variation.

Let latexmath:[\lambda_1,\ldots,\lambda_d] be the eigenvalues of the representation covariance matrix, and define the normalized eigenvalues

[latexmath]
++++

q_j=\frac{\lambda_j}{\sum_{\ell=1}^{d}\lambda_\ell}.
++++

The effective rank is the exponential of the entropy of this distribution:

[latexmath]
++++

\exp\left(-\sum_{j=1}^{d}q_j\ln q_j\right).
++++

If the variance is distributed equally across all latexmath:[d] directions, the effective rank is latexmath:[d]. If all variation lies in one direction, the effective rank is one. Intermediate values indicate that variation is distributed across a smaller number of directions.

The normalization removes overall scale. Multiplying every representation by latexmath:[10^{-5}] does not change the effective rank, because all covariance eigenvalues are multiplied by the same squared factor and the normalized latexmath:[q_j] remain unchanged. This is useful for measuring dimensional collapse, but it means effective rank cannot detect a representation whose spread has shrunk almost to zero.

The following excerpt is from the diagnostic code in ch03/06_collapse_demo.py. It computes both measurements from a matrix of representations.

[#ch3-listing-L07,reftext={chapter}.{counter:listing},caption='{listing-caption}.{counter:listing-number} ']
.Measuring spread and effective rank
[source,python]
----
def feature_diagnostics(features):
    features = np.asarray(features, dtype=np.float64)
    centered = features - features.mean(axis=0, keepdims=True)
    singular_values = np.linalg.svd(centered, compute_uv=False)
    eigenvalues = singular_values ** 2                   #A
    total = float(eigenvalues.sum())
    if total <= 1e-15:
        rank = 0.0
    else:
        q = eigenvalues / total                           #B
        entropy = -np.sum(q * np.log(np.maximum(q, 1e-15)))
        rank = float(np.exp(entropy))                     #C
    spread = float(np.std(features, axis=0).mean())       #D
    return {"mean_dim_std": spread, "effective_rank": rank}
----

A The squared singular values give the covariance eigenvalues up to a common factor.

B Normalizes the eigenvalues, removing the influence of overall scale.

C Computes the effective rank from the entropy.

D Averages the standard deviation across representation coordinates.

The full repository function also validates its input and handles the degenerate all-zero case. We use this diagnostic on the encoder output, not just the projection head, because the encoder output is the representation retained for later use.

A small spread is not, on its own, proof that a representation contains no information. A representation can encode distinctions at a small scale. The recorded experiment does not probe the attraction-only encoder for physical-state information, so we do not claim that its tiny variation is necessarily useless. The result is narrower: the objective does not demand spread or prevent a constant representation from minimizing the loss.

==== Why does NT-Xent behave differently? If all views map to the same nonzero vector, every cosine similarity is one. The positive and the negatives then have identical scores, so the probability assigned to the positive is latexmath:[1/(2N-1)] and the loss is latexmath:[\ln(2N-1)]. The encoder cannot reduce the loss by distinguishing the positive from the negatives, because it has collapsed them all together. NT-Xent rewards a lower loss when the positive receives a higher score than the negatives.

The negative pairs therefore give contrastive learning a mechanism that attraction alone lacks. But they bring their own design choices, including the number and quality of the negatives. The next section examines alternatives that do not require them.

=== 3.4.2 Three mechanisms in brief

SimSiam, BYOL, and Barlow Twins use different mechanisms to avoid collapse without contrastive negative pairs. Their shared starting point is that two views of the same frame should produce related representations. What differs is how each method prevents that requirement from being satisfied by an uninformative constant output.

The repository implements reduced-scale versions of all three methods. The study uses cart-pole frames, five random seeds, 30 epochs, up to 6,000 training frames, batch size 128, and Adam with learning rate latexmath:[10^{-3}]. The encoder output has 32 dimensions, while the projection and predictor heads use 128-dimensional embeddings. These experiments examine the core mechanisms at small scale; they are not exact reproductions of the large-scale ImageNet experiments in the original papers.

==== SimSiam: stop the gradient through the target

SimSiam uses a shared encoder and projector for the two views, plus a predictor applied to one branch. Let latexmath:[z_1,z_2] be the projected representations and latexmath:[p_1,p_2] their predictor outputs.

For a predictor output latexmath:[p] and target representation latexmath:[z], define the negative cosine similarity:

[latexmath]
++++

D(p,z)=-
\frac{p}{\lVert p\rVert_2}
\cdot
\frac{z}{\lVert z\rVert_2}.
\tag{3.9}
++++

The symmetric objective evaluates each view as the prediction and the other view as the target:

[latexmath]
++++

\frac12D\big(p_1,\operatorname{sg}(z_2)\big)
+
\frac12D\big(p_2,\operatorname{sg}(z_1)\big)
\tag{3.10}
++++

The operator latexmath:[\operatorname{sg}] means stop-gradient. It leaves the target’s value unchanged, but treats it as a constant when calculating the gradient. The predictor is trained to match the opposite branch’s representation, while the target branch does not receive gradients through that particular loss term.

This asymmetry is central to SimSiam. The method also uses a projector and a predictor with batch normalization, following its original design. The stop-gradient changes the optimization process, but it is not a universal mathematical guarantee that every possible configuration avoids collapse. Its effectiveness is established primarily through the method’s experiments, and our reduced-scale study measures the result of the full configuration rather than performing an ablation of each component.

==== BYOL: a slowly moving target

BYOL also compares online predictions with target representations, but its target branch is a separate network. The online network contains an encoder, projector, and predictor and is updated by gradient descent. The target network contains an encoder and projector, receives no gradient, and changes through an exponential moving average of the online parameters.

Let latexmath:[\theta_o] denote the online parameters, latexmath:[\theta_t] the target parameters, and latexmath:[m\in[0,1]) the momentum. The update is

[latexmath]
++++

\boxed{
\theta_t\leftarrow m\theta_t+(1-m)\theta_o
}
\tag{3.11}
++++

The target therefore changes gradually rather than tracking every online update immediately. The online network learns to predict the slowly changing target. In the repository implementation, the momentum starts at 0.99 and increases toward one during training using a cosine schedule.

The target network is not optimized by gradient descent. Its parameters are updated by the exponential moving average, which provides the asymmetry in BYOL’s learning procedure. As with SimSiam, this mechanism is not a general proof of collapse prevention for every configuration. The experiment tests the implemented method at the declared scale and budget.

def simsiam_loss(p1, z2, p2, z1):
    def d(p, z):
        p = F.normalize(p, dim=1)
        z = F.normalize(z.detach(), dim=1)               #A
        return -(p * z).sum(dim=1).mean()                 #B

    return 0.5 * d(p1, z2) + 0.5 * d(p2, z1)             #C


def update_target_ema(online_model, target_model, decay=0.99):
    with torch.no_grad():
        for po, pt in zip(
            online_model.parameters(), target_model.parameters()
        ):
            pt.data.mul_(decay)                           #D
            pt.data.add_(po.data, alpha=1.0 - decay)
----

A Detaches the target from the gradient computation.

B Computes negative cosine similarity for the batch.

C Averages the two directions, as in equation 3.10.

D Moves the target parameters toward the online parameters, as in equation 3.11.

The code above contains two distinct mechanisms. SimSiam stops the gradient through the target representation; BYOL updates the target network by exponential moving average. They should not be conflated: BYOL’s target-network update is not simply another spelling of SimSiam’s stop-gradient.

==== Barlow Twins: reduce redundancy between coordinates

Barlow Twins takes a different approach. It standardizes each coordinate of the two embedding batches and computes their cross-correlation matrix. If the views agree coordinate by coordinate, the diagonal should approach one. If different coordinates are uncorrelated, the off-diagonal entries should approach zero.

Let latexmath:[\hat z^A_{b,i}] and latexmath:[\hat z^B_{b,j}] denote standardized coordinates latexmath:[i] and latexmath:[j] for frame latexmath:[b] in two view batches. The cross-correlation matrix is

[latexmath]
++++

C_{ij}=\frac1N\sum_{b=1}^{N}
\hat z^A_{b,i}\hat z^B_{b,j}.
\tag{3.12}
++++

The loss penalizes deviation of diagonal entries from one and penalizes nonzero off-diagonal entries:

[latexmath]
++++

\sum_i(1-C_{ii})^2
+
\lambda\sum_i\sum_{j\ne i}C_{ij}^2
\tag{3.13}
++++

The diagonal term rewards agreement across views. The off-diagonal term discourages different dimensions from carrying redundant, linearly correlated information. The implementation uses latexmath:[\lambda=0.005].

A constant coordinate cannot be standardized into a meaningful unit-variance signal. The code clamps the standard deviation at latexmath:[10^{-6}]; if a coordinate is constant, its standardized values are zero, and its diagonal term contributes a penalty of one. Collapse therefore incurs a positive loss. However, because the method standardizes the features, this objective does not set a minimum scale for the unstandardized representation itself.

Source: worldmodels/losses/noncontrastive.py.

[#ch3-listing-L09,reftext={chapter}.{counter:listing},caption='{listing-caption}.{counter:listing-number} ']
.The Barlow Twins cross-correlation loss

[source,python]
----
def barlow_twins_loss(z1, z2, lambd=0.005):
    n, d = z1.shape
    s1 = z1.std(dim=0, unbiased=False).clamp_min(1e-6)
    s2 = z2.std(dim=0, unbiased=False).clamp_min(1e-6)
    a = (z1 - z1.mean(dim=0)) / s1                      #A
    b = (z2 - z2.mean(dim=0)) / s2
    c = a.T @ b / n                                     #B
    diag = (torch.diagonal(c) - 1).pow(2).sum()         #C
    off = ~torch.eye(d, dtype=torch.bool, device=z1.device)
    off_diag = c[off].pow(2).sum()                      #D
    return diag + lambd * off_diag
----

A Standardizes every coordinate across the batch.

B Computes the cross-correlation matrix in equation 3.12.

C Penalizes diagonal entries that differ from one.

D Penalizes off-diagonal correlations.

The mechanisms examined so far prevent collapse through asymmetry or relationships between coordinates. VICReg makes the requirements explicit in three terms: maintain agreement between views, keep variation in each coordinate above a floor, and reduce covariance between different coordinates.

=== 3.4.3 VICReg: making the anti-collapse force explicit

VICReg stands for variance-invariance-covariance regularization. It receives two batches of embeddings, latexmath:[Z^A] and latexmath:[Z^B], each with latexmath:[N] rows and latexmath:[d] coordinates. It combines three terms, each with a distinct purpose.

==== The variance term

The variance term sets a floor on the standard deviation of each coordinate across a batch. Let latexmath:[Z_{:,j}] denote column latexmath:[j], and let latexmath:[S] be its regularized standard deviation:

[latexmath]
++++

S(u)=\sqrt{\operatorname{Var}(u)+\epsilon}.
++++

The variance hinge is

[latexmath]
++++

\boxed{
v(Z)=\frac1d\sum_{j=1}^{d}
\max\big(0,\gamma-S(Z_{:,j})\big)
}
\tag{3.14}
++++

Here, latexmath:[\gamma] is the minimum target standard deviation and latexmath:[\epsilon>0] stabilizes the square root. The repository uses latexmath:[\gamma=1] and latexmath:[\epsilon=10^{-4}].

The hinge is zero for a coordinate whose standard deviation is already at least latexmath:[\gamma]. A coordinate below the threshold incurs a penalty proportional to the shortfall. The term therefore sets a floor; it does not reward arbitrarily increasing a coordinate’s scale.

The small latexmath:[\epsilon] matters near zero variance. Without it, differentiating the square root at zero can produce an undefined or unbounded derivative. With latexmath:[\epsilon=10^{-4}], the derivative of latexmath:[\sqrt{v+\epsilon}] with respect to variance is bounded above by latexmath:[1/(2\sqrt{\epsilon})=50].

==== The invariance term

The invariance term asks the two views to produce similar embeddings. In the implementation, it is the mean squared error between matching rows:

[latexmath]
++++

\boxed{
s(Z^A,Z^B)=
\frac{1}{Nd}
\sum_{n=1}^{N}
\left\lVert z_n^A-z_n^B\right\rVert_2^2
}
\tag{3.15}
++++

This is the positive-view attraction from the collapse demonstration, but now it is only one part of the objective. By itself, it would allow a constant representation. In VICReg, the variance and covariance terms constrain what solutions can minimize the total loss.

==== The covariance term

The covariance term discourages redundancy between different coordinates. Let latexmath:[\bar z] be the mean row of the batch. Define the sample covariance matrix

[latexmath]
++++

C(Z)=\frac{1}{N-1}
\sum_{n=1}^{N}
(z_n-\bar z)(z_n-\bar z)^\top.
++++

Its diagonal contains the coordinate variances. Its off-diagonal entries contain the covariances between different coordinates. The VICReg covariance term penalizes squared off-diagonal entries:

[latexmath]
++++

\boxed{
c(Z)=\frac1d
\sum_{i\ne j}[C(Z)]_{ij}^{2}
}
\tag{3.16}
++++

If all off-diagonal entries are zero, the coordinates are pairwise uncorrelated in the batch. This reduces second-order redundancy, but it does not establish that the coordinates are statistically independent: nonlinear dependence can remain even when covariance is zero.

==== Combining the three terms

==== The total VICReg loss is a weighted sum

[latexmath]
++++

\boxed{
\begin{aligned}
L_{\mathrm{VICReg}}
={}&\lambda s(Z^A,Z^B)\\
&+\mu\big[v(Z^A)+v(Z^B)\big]\\
&+\nu\big[c(Z^A)+c(Z^B)\big].
\end{aligned}
}
\tag{3.17}
++++

The implementation uses latexmath:[\lambda=25], latexmath:[\mu=25], and latexmath:[\nu=1]. These coefficients set the relative influence of invariance, variance, and covariance penalties. Both embedding batches receive their own variance and covariance penalties.

Consider what the three terms do to degenerate solutions.

*A constant representation.* If every coordinate is constant across the batch, the invariance term is zero and the covariance term is zero. But the regularized standard deviation of each coordinate is only latexmath:[\sqrt{\epsilon}=0.01]. With latexmath:[\gamma=1], each coordinate incurs a variance-hinge penalty of latexmath:[0.99]. Across both views, the weighted variance term adds latexmath:[25\times2\times0.99=49.5] to the total loss. Collapse is no longer a zero-cost solution.

*A single repeated direction.* Suppose all coordinates are identical copies of one unit-variance scalar. The views can match and every coordinate meets the variance floor, so the invariance and variance terms can both be zero. But every off-diagonal covariance equals one. With latexmath:[d=16], there are latexmath:[16\times15=240] off-diagonal entries, and the covariance cost for each batch is latexmath:[240/16=15]. Across the two views, the covariance term contributes 30. This discourages dimensional collapse into one repeated direction.

*Unrelated but varied embeddings.* A model could produce embeddings with sufficient variance and little coordinate covariance without making the two views of the same frame agree. The variance and covariance terms would not necessarily penalize this configuration, but the invariance term would. It is the term that ties the representations of paired views together.

These examples show why no one of the three terms replaces the others. Variance prevents coordinates from becoming constant, covariance discourages redundancy, and invariance links representations of positive views. Their combination makes the constraints explicit, instead of relying solely on the behavior of the training procedure.

Source: worldmodels/losses/vicreg.py.

[source,python]
----
def vicreg_loss(za, zb, sim_coeff=25.0, std_coeff=25.0,
                cov_coeff=1.0, gamma=1.0, eps=1e-4):
    n, d = za.shape
    sim = F.mse_loss(za, zb)                             #A

    def variance(z):
        v = z.var(dim=0, unbiased=False)
        std = torch.sqrt(v + eps)                        #B
        return F.relu(gamma - std).mean()                #C

    def covariance(z):
        z = z - z.mean(dim=0)
        cov = (z.T @ z) / (n - 1)                       #D
        off = ~torch.eye(d, dtype=torch.bool, device=z.device)
        return cov[off].pow(2).sum() / d                 #E

    var = variance(za) + variance(zb)
    cov = covariance(za) + covariance(zb)
    total = sim_coeff * sim + std_coeff * var + cov_coeff * cov
    return total, sim, var, cov
----

A Computes the invariance term from equation 3.15.

B Computes the regularized standard deviation used by equation 3.14.

C Penalizes coordinates whose standard deviation is below latexmath:[\gamma].

D Computes the batch covariance matrix.

E Sums the squared off-diagonal entries, divided by latexmath:[d].

The variance calculation uses population variance, while the covariance estimate divides by (N-1), matching the repository implementation. The function returns the total loss and each of its three components so the training script can record their behavior separately.

== 3.5 Masked prediction

=== 3.5.1 From masked words to masked patches

BERT trains a language model by hiding selected tokens and asking it to predict them from the surrounding context. The targets are the identities of the missing tokens, not a human-written label for the whole sentence. The model learns from the structure already present in the text.

A masked autoencoder latexmath:[MAE] applies a related idea to images. It divides an image into patches, hides a random subset, and predicts the missing pixel values from the visible patches. The training target comes directly from the input image. No class label, action, reward, or physics state is required.

The masking ratio matters. If only a few patches are hidden, nearby visible pixels may make reconstruction relatively easy. Hiding a large fraction of the image creates a more demanding prediction task: the model must use the remaining patches and their relationships to reconstruct the missing content. The original MAE work found that a high masking ratio, such as 75%, could produce a useful self-supervised task at scale. That result motivates our choice; it does not establish that 75% is optimal for every dataset or architecture.

Our experiment uses latexmath:[64\times64] RGB frames from the Control Suite’s Cartpole Balance task. Each image is divided into an latexmath:[8\times8] grid, giving 64 patches. With a masking ratio of 75%, the encoder sees 16 randomly selected patches during training. The decoder predicts all 64 patches, but only the masked patches contribute to the loss.

This is an asymmetric architecture. The encoder processes the visible patches without carrying a placeholder token for every hidden patch. The decoder receives the encoded visible patches, inserts learned mask tokens into the missing positions, restores the original order, and predicts the pixel values. This division keeps the encoder’s training input smaller than the full image’s patch sequence.

There is an important boundary to the analogy with language. A rendered physics frame is far simpler than a natural image, and our images contain a stable background. Reconstructing a Cartpole frame is not the same as reconstructing the physical state that generated it. In particular, a single image need not reveal velocity. The experiment tests what this compact MAE learns under its particular data, architecture, and training budget.

=== 3.5.2 Building a masked autoencoder

The first operation is to turn an image into a sequence of patches. For a batch of images, the resulting tensor has shape

[latexmath]
++++

P\in\mathbb{R}^{B\times N\times D},
++++

where latexmath:[B] is the batch size, latexmath:[N=64] is the number of patches, and latexmath:[D=8\times8\times3=192] is the number of pixel-channel values in each flattened patch.

A learned linear layer embeds each patch into a 64-dimensional token. Positional embeddings distinguish the patches’ locations. The model then samples a different random mask for each image in the batch. It retains 16 tokens and sends only those tokens through the encoder.

def forward_encoder(self, x: torch.Tensor):
    patches = self.patchify(x)
    tokens = self.patch_embed(patches) + self.encoder_pos_embed
    b, n, d = tokens.shape
    len_keep = int(n * (1.0 - self.mask_ratio))

    noise = torch.rand(b, n, device=x.device)
    ids_shuffle = torch.argsort(noise, dim=1)
    ids_restore = torch.argsort(ids_shuffle, dim=1)
    ids_keep = ids_shuffle[:, :len_keep]
    visible = torch.gather(
        tokens, 1, ids_keep.unsqueeze(-1).expand(-1, -1, d)
    )

    mask = torch.ones(b, n, device=x.device)
    mask[:, :len_keep] = 0.0
    mask = torch.gather(mask, 1, ids_restore)

    encoded_visible = self.encoder_transformer(visible)
    z = encoded_visible.mean(dim=1)
    return z, encoded_visible, mask, ids_restore


def forward(self, x: torch.Tensor):
    patches = self.patchify(x)
    _, encoded_visible, mask, ids_restore = self.forward_encoder(x)
    pred_patches = self.forward_decoder(encoded_visible, ids_restore)
    loss = masked_mse_loss(patches, pred_patches, mask)
    return loss, pred_patches, mask
----

The random values in noise define a permutation of the patch positions. ids_keep selects the visible tokens, while ids_restore records how to put the visible tokens and mask tokens back into their original order for decoding. The mask uses 1 for a hidden patch and 0 for a visible patch. These details are important: a decoder must know which predicted patch belongs in which image location.

The training objective is the mean squared error over masked patches only. Let latexmath:[P_{bi}] denote patch latexmath:[i] from image latexmath:[b], let latexmath:[\hat P_{bi}] be its prediction, and let latexmath:[M_{bi}] equal 1 if that patch was masked and 0 otherwise. With latexmath:[D] pixel-channel values per patch, the loss is

[latexmath]
++++

\frac{
\displaystyle\sum_{b=1}^{B}\sum_{i=1}^{N}
M_{bi}\left[
\frac{1}{D}\sum_{j=1}^{D}
(P_{bij}-\hat P_{bij})^2
\right]
}{
\displaystyle\sum_{b=1}^{B}\sum_{i=1}^{N}M_{bi}
}.
\tag{3.18}
++++

The denominator counts masked patches, so each hidden patch contributes its mean pixel-channel error. Visible patches do not contribute to the loss, even though the decoder produces predictions for them too. This matches the implementation in masked_mse_loss.

The physics states collected from the simulator do not enter this objective. They remain available for evaluation, including the linear-probe tests used elsewhere in the chapter. The only training target here is the hidden image content.

=== 3.5.3 Reconstruction versus representation

A reconstruction loss measures how well the model rebuilds its input. A state probe asks a different question: how much information about the simulator’s state can be recovered by a linear map from the learned representation? Good reconstruction does not guarantee a strong state representation, just as a strong state probe does not guarantee pixel-accurate reconstruction.

Consider the target in equation 3.18. The error is measured across the pixels of every masked patch, including patches containing the floor and background. These pixels are part of the image and therefore part of the objective, even when their appearance says little about the cart’s position or the pole’s angular velocity. The encoder can be rewarded for retaining information that helps reconstruct pixels without being equally rewarded for making every physical variable easy to decode linearly.

This is a hypothesis about the objective, not a conclusion that follows from the equation alone. We test it by examining reconstructions and measuring frozen-feature linear probes. The interpretation must remain bounded by the experiment: Cartpole frames at latexmath:[64\times64], the current patch-transformer architecture, a 75% masking ratio, and the stated training budget. These frames are far simpler than natural video, so this comparison does not establish a general ranking of reconstruction and contrastive methods.

== 3.6 Latent bottlenecks and compact state

=== 3.6.1 The information bottleneck as a lens

Let latexmath:[X] denote an observation, latexmath:[Z] its learned representation, and latexmath:[Y] a task-relevant variable. For a world model, latexmath:[X] might be an image and latexmath:[Y] might describe the physical state needed to predict what happens next.

The information bottleneck asks for a representation that preserves information relevant to latexmath:[Y] while discarding as much unnecessary information about latexmath:[X] as possible. One way to express this trade-off is

[latexmath]
++++

\mathcal{L}_{\mathrm{IB}}
= I(Z;X)-\beta I(Z;Y).
\tag{3.19}
++++

Here, latexmath:[I(A;B)] is the mutual information between random variables latexmath:[A] and latexmath:[B]. It measures statistical dependence: it is zero when the variables are independent and increases as knowing one variable provides more information about the other. The coefficient latexmath:[\beta] controls the exchange between compression and relevance.

The two terms pull in opposite directions.

*Compression.* Minimizing latexmath:[I(Z;X)] discourages the representation from carrying information about every detail of the input.

*Relevance.* Minimizing the full loss rewards a large latexmath:[I(Z;Y)], because that term is subtracted. The representation should preserve information that helps distinguish task-relevant outcomes.

When latexmath:[\beta] is small, compression receives more weight relative to relevance. As latexmath:[\beta] increases, preserving information about latexmath:[Y] becomes more important. The best trade-off depends on which information the task actually needs.

This gives a useful interpretation of a compact state. If an image contains a cart, a pole, a floor, lighting, and background details, the agent may not need to encode all those details equally. It needs enough information to distinguish states that matter for prediction and control. But compression must stop before two physically different situations that require different decisions become indistinguishable in the representation.

That is the connection to the contracts from Chapter 2. A representation needs sufficiency for the task, but minimality asks it not to retain unnecessary detail. A bottleneck can help with the second goal while making the first harder to satisfy.

There is an important distinction between this information-theoretic objective and simply choosing a small vector. A deterministic encoder with a low-dimensional continuous output is not, by that fact alone, optimizing latexmath:[I(Z;X)]. In formal information-bottleneck formulations, the relationship between input and representation is treated probabilistically, and the mutual-information terms must be defined and optimized or bounded appropriately. A deterministic autoencoder with a narrow latent layer imposes a practical capacity constraint; it does not automatically implement equation 3.19.

The same distinction applies to VICReg. Its invariance, variance, and covariance penalties encourage particular properties of learned embeddings, but VICReg does not optimize the information-bottleneck objective in equation 3.19. The equation is a conceptual lens for understanding what we want from a representation, not a claim that every self-supervised objective is secretly an information-bottleneck algorithm.

In this chapter’s experiments, the simulator’s physics state remains an evaluation target. The contrastive loss does not receive that state as a training label, and the latent-dimension sweep does not calculate mutual information directly. We use a linear probe to measure one concrete property: how much of the state is linearly recoverable from the learned features.

=== 3.6.2 Choosing the latent dimension

The practical question is how many dimensions the encoder needs. It is tempting to set the latent dimension equal to the number of physical state variables. That is not a reliable rule.

A physical variable need not map to one latent coordinate. A learned feature can combine several state variables, and a single variable may require several features to become easy to decode. This is especially relevant to angles: a linear probe can have difficulty reading an angle directly near the wraparound boundary, so the evaluation uses periodic encoding and a circular R² score for angular positions.

Nor does a larger latent dimension automatically make the representation better. The encoder may fail to learn useful features within the available training budget, or its additional coordinates may not improve the information that the probe can recover. The dimension is a capacity choice; the probe is a measurement of the result.

==== The hypothesis

The benchmark supplies two tasks with different physical-state dimensions:

Cartpole Balance: four state variables.

Cheetah Run: eighteen state variables.

The hypothesis is that Cartpole will reach a useful probe-performance plateau at a smaller latent dimension, while Cheetah will benefit from larger representations for longer. At latexmath:[d=2], Cartpole’s representation may be too restrictive to preserve the variation needed to distinguish its physical states.

This hypothesis concerns the performance of the complete learned representation, not just the arithmetic difference between the number of latent dimensions and the number of state variables. A four-variable system does not imply that a four-dimensional latent is sufficient, nor that four is the optimal dimension for a linear probe.

==== The experiment

The repository’s ch03/10_bottleneck_sweep.py trains a separate contrastive encoder for every combination of task, latent dimension, and random seed. The dimensions are latexmath:[d\in{2,4,8,16,64,256}], with seeds 0, 1, and 2. Each run uses the convolutional encoder from Section 3.3, with a projection head whose output dimension matches latexmath:[d].

The run uses Adam with a learning rate of latexmath:[10^{-3}], a batch size of 64, and 10 training epochs. It selects 3,000 training frames and 1,000 validation frames, spreading the selected indices across episodes rather than taking a single prefix of each dataset. The contrastive objective operates on two augmented views of each frame. Once training is complete, the linear probe is fitted to the frozen encoder features, not the projection head’s output.

SIDEBAR — The bottleneck in one paragraph. The latent dimension limits the coordinates available to the representation. Too little capacity can make task-relevant distinctions difficult to preserve; more capacity can improve decodability, but also costs computation and may not help the task. The right dimension is not automatically the state-vector length. It is the smallest practical representation that retains enough information for the work the agent must do, judged by measurements relevant to that work.

The distinction between reconstruction, invariance, and predictive information now becomes more concrete. Section 3.5 showed that reconstructing pixels does not guarantee that state is linearly available. This section shows that even a representation with more dimensions is useful only to the extent that it preserves the distinctions a probe can recover. In the next section, the question changes from which static observations should agree to which future observation follows from the past.

== 3.7 Predicting over time: from invariance to prediction

=== 3.7.1 Why the future is not just another view

Return to the view-generation decision from Section 3.3. Two augmented versions of the same frame are positive examples because the objective asks the encoder to preserve information that survives those augmentations. The brightness and small crop changes are intended to be nuisance variations, so the learned representation should be relatively insensitive to them.

Now suppose we instead pair frames from times latexmath:[t] and latexmath:[t+\Delta] as positives and ask their embeddings to agree. The scene may have changed during that interval. The cart may have moved, the pole may have rotated, and the object’s velocity may have changed. An objective that rewards agreement between the two embeddings can treat these differences as information to suppress.

That may be undesirable for a world model. The future depends on the current situation and its dynamics. If the representation is encouraged to remove the differences that signal those dynamics, a downstream predictor has less useful information to work with.

This is not a claim that temporal contrastive learning must always discard dynamics. The result depends on how temporal positives are constructed and what else the objective asks the model to preserve. The narrower point is that invariance and prediction impose different requirements. Invariance says which observations should agree; prediction says which future observations are compatible with a given past.

Our measurements from the earlier sections make this distinction concrete. Table 3.2 showed that velocity was poorly decoded from the learned single-frame representation under the tested configuration. Stacking two frames did not reliably fix the problem under those same experimental conditions. These results do not prove that velocity is fundamentally absent from images or impossible to recover from short sequences. They show that the representation and training setup did not make it reliably linearly available.

A frame-level invariance objective has no direct reason to preserve velocity. A temporal objective can instead reward a context for retaining information that helps identify a future observation. CPC is one way to implement that change.

=== 3.7.2 Contrastive predictive coding

CPC, introduced by van den Oord and colleagues, learns by predicting future representations rather than reconstructing future pixels. It encodes a sequence of observations into latent vectors, summarizes the available past in a context vector, and trains that context to identify the correct future latent among other candidates.

Let a sequence of observations be latexmath:[x_1,x_2,\ldots,x_T]. A shared encoder latexmath:[f_\theta] maps each observation to a latent representation:

[latexmath]
++++

z_t=f_\theta(x_t).
++++

A recurrent model summarizes the representations observed up to time latexmath:[t]:

[latexmath]
++++

c_t=g(z_1,z_2,\ldots,z_t).
++++

The context latexmath:[c_t] may depend on the current representation and every earlier representation in the sequence. It must not depend on future representations latexmath:[z_{t+1},z_{t+2},\ldots]. Otherwise, the task would leak information from the answer into the context used to select that answer.

We use a gated recurrent unit latexmath:[GRU] for latexmath:[g]. A GRU maintains a learned hidden state as it processes the sequence one step at a time. Its purpose here is to produce a compact context vector, not to guarantee that every relevant aspect of the past is retained. Whether the learned context retains useful information is an empirical question.

==== Scoring a candidate future

For each prediction horizon latexmath:[k], CPC learns a matrix latexmath:[W_k]. It scores a candidate future latent using a bilinear compatibility function:

[latexmath]
++++

\exp\!\left(z_{t+k}^{\top}W_kc_t\right).
\tag{3.20}
++++

Here, latexmath:[z_{t+k}] is the candidate representation at a future time, latexmath:[c_t] is the context available at time latexmath:[t], and latexmath:[W_k] is specific to horizon latexmath:[k]. The matrix lets the model learn which relationships between context coordinates and future latent coordinates are useful for identifying a match.

The exponent turns the raw bilinear score into a positive compatibility value. As in equation 3.5, the objective normalizes these values across candidates to obtain a probability distribution. Higher compatibility means that a candidate receives a larger share of the probability assigned by the context.

Consider a batch containing latexmath:[B] sequences. For a context from sequence latexmath:[i], the correct target is the future latent from sequence latexmath:[i]. Future latents from the other sequences in the batch act as negative candidates. At horizon latexmath:[k], define the raw score

[latexmath]
++++

\left(z_{t+k}^{(j)}\right)^\top
W_kc_t^{(i)},
++++

where latexmath:[i] identifies the context and latexmath:[j] identifies a candidate future. The probability assigned to the correct candidate is

[latexmath]
++++

\frac{\exp(s_{ii}^{(k)})}
{\displaystyle\sum_{j=1}^{B}\exp(s_{ij}^{(k)})}.
++++

The loss for that context and horizon is the negative log-probability of the correct match. Averaging across contexts and trained horizons gives the multi-horizon InfoNCE objective:

[latexmath]
++++

-\frac{1}{|\mathcal{I}|}
\sum_{(i,t,k)\in\mathcal{I}}
\log
\frac{\exp(s_{ii}^{(k)})}
{\displaystyle\sum_{j=1}^{B}\exp(s_{ij}^{(k)})},
++++

where latexmath:[\mathcal{I}] is the set of valid context, sequence, and horizon combinations in the batch. This is equation 3.5 aimed at a different task. Instead of identifying which view belongs to the same observation, it identifies which future latent belongs to the current context.

The model is trained at several horizons. A one-step prediction head scores the latent at (t+1); a two-step head scores (t+2); a three-step head scores (t+3). Each head has its own matrix latexmath:[W_k]. The context is shared, so its representation must support identification of future latents at each of these horizons.

The model does not directly regress the future latent with a squared-error objective. It does not take a predicted vector, feed that vector back into the model, and recursively generate a long sequence. It learns compatibility scores that rank the correct future above other candidates. Those are distinct tasks, and the evaluation must respect that distinction.

==== The implementation

[#ch3-listing-L12,reftext={chapter}.{counter:listing},caption='{listing-caption}.{counter:listing-number} ']

[source,python]
----
z_seq = self.encode_sequence(x_seq)
c_seq, _ = self.gru(z_seq)

b, t, _ = z_seq.shape
cpc_sum = torch.zeros((), device=x_seq.device)
n_cpc = 0

for t_idx in range(0, t - self.k_steps):
    c_t = c_seq[:, t_idx]
    for k in range(self.k_steps):
        target = z_seq[:, t_idx + 1 + k]
        pred = c_t @ self.w_k[k].T
        logits = pred @ target.T
        labels = torch.arange(b, device=x_seq.device)
        cpc_sum = cpc_sum + F.cross_entropy(logits, labels)
        n_cpc += 1

return cpc_sum / n_cpc
----

The matrix multiplication produces a batch-by-batch score matrix. Row latexmath:[i] contains the scores assigned by context latexmath:[i] to every candidate future latent in that batch. The correct target lies on the diagonal, because context and future target come from the same sequence. Cross-entropy encourages the diagonal score to dominate its row.

The GRU is unidirectional. Although the implementation processes a tensor containing multiple time steps at once, the context output at index latexmath:[t] is computed causally from the sequence up to that time step. Future latents are targets used to calculate the loss; they are not inputs to the context at latexmath:[t].

WARNING — Causality. A context used to predict the future may contain the current observation and earlier observations, but not the future target. If future frames influence the context, the model can identify the target using information that would not be available at prediction time.

==== What enters the experiment

The CPC experiment uses Cartpole Balance frames collected under a uniform random policy. The model receives sequences of images. It does not receive the actions that generated those sequences.

That omission matters. In a controlled physical system, the next state depends not only on the current state but also on the action applied and the system’s dynamics. CPC here learns from a sequence generated by an unknown-to-the-model action stream. Its context must infer useful information from the visual history alone.

This experiment is therefore not a controlled comparison between action-conditioned and action-free prediction. It does not tell us how much actions would improve the results. The missing action input is a limitation of this setup and one reason the next chapter treats predictive representations and action-conditioning as separate design questions.

=== 3.7.3 CPC evaluation: future retrieval and state probes

A low CPC loss means that the correct future latent receives high probability under the model’s candidate distribution. But the loss alone is harder to interpret than a direct retrieval measurement. We therefore evaluate the trained compatibility scores on held-out sequence windows and ask whether the correct future latent ranks above the other candidates.

This evaluation is aligned with the objective CPC actually trains. It is not a physical-state rollout experiment.

==== Evaluation protocol

The committed run uses five trained model seeds: 0 through 4. Each model was trained for 20 epochs with a batch size of 32, learning rate latexmath:[10^{-3}], encoder latent dimension 16, GRU context dimension 32, and three prediction horizons. The training configuration caps the data at 4,000 training sequence windows and 1,000 validation sequence windows, each of length 16 frames.

For the primary retrieval evaluation, the experiment selects 200 non-overlapping, episode-safe windows from the validation split. The selection is balanced across five validation episodes, with 40 windows per episode. The windows do not overlap within their source episodes, and they are shuffled into evaluation batches so that candidate sequences are not adjacent windows presented in temporal order. These 200 windows are not 200 independent trajectories; they come from only five validation episodes.

Evaluation compares each context’s correct future latent with the corresponding future latents from other sequences in the same batch. There are six full batches of 32 candidates and a final batch of eight. The chance level is consequently computed for this query-weighted, in-batch protocol:

[latexmath]
++++

\frac{192(1/32)+8(1/8)}{200}=0.035=3.5\%
++++

The random top-1 chance rate is therefore 3.5%, rather than latexmath:[1/200]. The test does not rank each context against all 200 windows simultaneously. That distinction is part of the result, not a detail to omit from the caption.

==== Future-latent retrieval

The top-1 retrieval rate is the fraction of queries for which the matching future latent receives the highest score in its batch. Top-5 retrieval counts a match as correct if it appears among the five highest-scoring candidates. The positive-minus-hardest-negative margin measures the score gap between the correct future and the most competitive incorrect candidate. Because the logits are raw bilinear scores, that margin is a score difference, not a probability.

These metrics are consistent with identifying the matching future latent becoming less separated from other candidates at longer horizons, even though the correct candidate remains ranked first most of the time.

Top-5 retrieval reaches 100% in each seed at all three horizons. This tells us that the positive candidate reliably appears among the five highest-scoring candidates in the batches used for evaluation. It does not mean the model can predict five steps into the future with perfect physical accuracy.

The candidate protocol also limits the claim. Candidates come from only the selected validation windows and are compared within batches; the benchmark does not test retrieval across every possible future state or every possible trajectory. The five episodes contribute many windows, but windows from the same episode are not independent evidence of generalization to wholly new environments.

The recurrent context has a numerically higher current cart-position R² than the static encoder: 0.805 versus 0.770. Its mean next-state R² across the four state variables is also numerically higher, at 0.259 ± 0.016, compared with 0.238 ± 0.009 for the static representation. The per-variable measurements show that this change is limited. Cart velocity remains very weakly decodable, and pole angular velocity remains negative under both representations.

Negative R² means that the probe performs worse on the validation samples than a constant predictor based on the validation-target mean. It does not prove that the representation contains no information about that variable; it says the fitted linear readout does not recover it effectively under this evaluation.

The variation across seeds also matters. The context’s cart-position score varies more from seed to seed than the static score, and the study does not establish statistical significance for the differences between the two representations. It would be too strong to conclude that adding a GRU solves state estimation or makes velocity available. The measurement supports a more limited result: the recurrent context changes what is linearly available, but the change is not uniform across physical variables.

==== What the experiment establishes

The primary result is that the trained CPC compatibility function identifies matching future latents substantially above the protocol’s 3.5% random-candidate chance level. Its retrieval performance remains high over three trained horizons, while the loss and margin indicate somewhat less separation at longer horizons.

The state probes provide a complementary picture. Current position is relatively well represented, but velocity remains poorly decoded from both the static latent and the recurrent context. High future-latent retrieval therefore does not imply that every physical variable is explicitly available in the representation. Nor does it establish that the model can predict a physical state recursively, remain stable across long rollouts, or support a useful planner.

The experiment also receives no action input. Because the frames were generated under a random policy, the learned context does not distinguish state-driven change from the effects of the actions taken. The study is not a controlled test of action-conditioning; it simply does not include it. We must not interpret the retrieval score as action-conditioned transition prediction or as a universal ceiling on what CPC can achieve.

WARNING — A GRU is a placeholder, not a memory guarantee. The context vector summarizes a finite sequence through a learned recurrent state. A GRU does not guarantee that information needed over long periods will be retained. The memory chapter returns to that question using an environment designed to test long-term memory, rather than treating this short-window retrieval task as a memory benchmark.

CPC provides a bridge between the objectives in this chapter and the predictive representations discussed next. Instead of enforcing agreement between two observations or rebuilding missing pixels, it asks a context to identify a future embedding. Chapter 4 develops the joint-embedding predictive idea further through JEPA architectures, with a different emphasis on learned prediction targets and, later, action-conditioning.

We now have several ways to train a visual representation. Contrastive learning encourages agreement across views. Non-contrastive objectives add mechanisms to prevent collapse. Masked prediction trains a model to reconstruct hidden pixels, and CPC asks a context to identify a future representation.

These methods differ in what they reward, but the agent should not need a different interface for every training objective. Once an encoder has been trained, the agent needs a component that accepts an observation and returns a representation. If the agent maintains a recurrent state, the same component must also update that state as new observations arrive.

This is where the chapter’s work returns to the agent loop from Chapter 1. We will use a trained contrastive encoder behind a common interface. The dynamics and reward components remain placeholders; this section assembles the representation component rather than claiming to complete the world model.

== 3.8 Assembling the encoder

=== 3.8.1 A common encoder interface

The current repository implements the shared interface in `+worldmodels/models/encoders.py+`. The Encoder class wraps a backbone, such as the ConvEncoder trained in Section 3.3. It exposes two methods:

`+encode(obs)+` maps an observation to its latent representation.

`+update(state, obs)+` processes the observation and returns the updated agent state.

The second method can operate in either of two ways. Without a recurrent layer, it simply returns the encoded observation. With a recurrent layer, it passes the representation and previous recurrent state through a GRU cell. On the first call, when no previous state exists, it initializes the hidden state to zeros.

Source: `+worldmodels/models/encoders.py+`. The excerpt below is taken from the canonical implementation.

[#ch3-listing-L13,reftext={chapter}.{counter:listing},caption='{listing-caption}.{counter:listing-number} ']
.The encoder interface

[source,python]
----
class Encoder(nn.Module):
    """Unified encoder interface used by the Chapter 1 agent loop."""

    def __init__(
        self,
        backbone: nn.Module,
        recurrent_hidden_dim: Optional[int] = None,
    ) -> None:
        super().__init__()
        self.backbone = backbone
        self.recurrent_hidden_dim = recurrent_hidden_dim
        if recurrent_hidden_dim is not None:
            latent_dim = getattr(backbone, "latent_dim", 16)
            self.gru_cell = nn.GRUCell(
                latent_dim, recurrent_hidden_dim
            )
        else:
            self.gru_cell = None

    def encode(self, obs: torch.Tensor) -> torch.Tensor:
        if obs.ndim == 3:
            obs = obs.unsqueeze(0)
        return self.backbone(obs)

    def update(
        self,
        state: Optional[torch.Tensor],
        obs: torch.Tensor,    ) -> torch.Tensor:
        z = self.encode(obs)
        if self.gru_cell is None:
            return z
        if state is None:
            state = torch.zeros(
                z.shape[0],
                self.recurrent_hidden_dim,
                device=z.device,
                dtype=z.dtype,
            )
        return self.gru_cell(z, state)
----

The wrapper keeps the representation-learning architecture separate from the agent’s interface. The backbone determines how observations are encoded. The optional GRU cell determines how successive encodings are combined into a persistent hidden state.

The word state in this interface refers to the encoder’s recurrent hidden state, not the simulator’s ground-truth physical state. During normal operation, the agent does not receive qpos or qvel from the simulator. It receives the rendered observation and carries its own internal state between calls.

The wrapper also does not dictate how the encoder was trained. A different compatible backbone can be substituted without changing the calls made by the agent loop. The interface is small, but it creates an important separation: training objectives can change while the rest of the agent continues to consume an observation and an updated internal state.

=== 3.8.2 Verifying the contract

The repository’s ch03/12_assemble_encoder.py runner checks this interface using a saved contrastive encoder checkpoint. It loads the encoder with a latent dimension of 16 and wraps it with a recurrent hidden dimension of 32. The script then processes ten validation frames in order, passing the previous hidden state into each subsequent update.

The expected recurrent-state shape is `+(1, 32)+`. The committed output in ch03/results/table_03_06_synthesis.json records that shape and the ten frames tested.

This is an interface smoke test, not an evaluation of representation quality. It verifies that the checkpoint loads, the encoder processes observations, and the recurrent-state contract holds for the tested sequence. It does not establish that the representation is sufficient for control, that the recurrent state captures all relevant history, or that the assembled agent can act successfully in the environment.

The interface therefore completes a software contract, not the scientific contract from Chapter 2. Whether the representation is useful depends on the measurements from the preceding sections and on what the later dynamics and reward components require.

=== 3.8.3 What each objective pays to preserve

The experiments show why a common interface does not imply that all encoders learn equivalent representations. The objective used during training determines which relationships are rewarded. Table 3.5 summarizes the central trade-off from this chapter.



[#ch3-table-T05,reftext={chapter}.{counter:table},caption='{table-caption}.{counter:table-number} ']
.Representation objectives and their trade-offs
[width="100%",cols="25%,25%,25%,25%",options="header",]
|===
|Objective |Paid to keep |May discard |Invited failure
|Pretext tasks |Task-defined structure |Variables irrelevant to the pretext |Shortcut features
|Contrastive (NT-Xent) |Structures preserved across views |Information removed by augmentation |False negatives and aggressive invariance
|Non-contrastive methods |Invariant, non-collapsed coordinates |Redundant coordinates |Collapse if the anti-collapse mechanism fails
|Masked autoencoding |Information useful for reconstruction |Details irrelevant to pixel recovery |Capacity spent on predictable pixels
|Temporal CPC |Information useful for future prediction |Unpredictable innovations |Action-unconditioned prediction ceiling
|===

The table is not a ranking. Each row describes the direct pressure imposed by a family of objectives, together with a corresponding risk. Whether a particular model actually suffers that failure must be measured.

Pretext tasks define their own prediction target. That target can create useful supervision from the structure of observations, but it can also reward shortcuts that solve the pretext without preserving the information needed downstream.

Contrastive learning pays for agreement across the views constructed by the augmentation pipeline. This is useful when the chosen transformations preserve task-relevant distinctions. It becomes a problem when an augmentation removes information the agent needs, or when different frames that look similar become false negatives.

Non-contrastive methods demonstrate that negatives are not the only way to prevent collapse. SimSiam, BYOL, Barlow Twins, and VICReg use different mechanisms to constrain the learned representation. Those mechanisms introduce their own design choices, and the reduced-scale experiments in this chapter do not establish a universal ranking of the methods.

Masked autoencoding pays for reconstructing missing pixel content. It may devote capacity to background or other predictable image details that do not make physical variables easy to decode. The Cartpole experiment found that reconstruction quality and state-probe quality are distinct measurements.

CPC changes the target from reconstructing an observation to identifying its future representation from a context. The retrieval experiment shows that the correct future latent can be identified at high rates within the tested candidate batches. Its state probes remain weak for velocity, and the model receives no action input. Future-latent identification alone is therefore not a guarantee of a complete predictive state.

The common pattern is that an objective cannot be judged solely by whether its loss decreases. We need to examine what its representation preserves, what it discards, and whether those properties match the agent’s requirements.

== Summary
* Pretext tasks: Rotation prediction, jigsaw prediction, and colorization create supervision from the structure of observations. Their limitation is that solving a pretext task does not guarantee that the representation preserves the information needed by a world model. The chosen prediction target determines what the model is paid to learn.
* Contrastive learning: NT-Xent turns the identification of matching views into a classification problem, using similarities between positive and negative examples. On Cartpole, the training loss fell from approximately 3.78 to 3.11 over 15 epochs across the three-seed run. State probes showed that positions were more linearly accessible than velocities, and stacking two consecutive frames did not reliably improve velocity decoding under the tested configuration.
* Collapse and its remedies: An attraction-only objective has a trivial constant-representation solution, so agreement between views is not enough. SimSiam, BYOL, Barlow Twins, and VICReg introduce different mechanisms to avoid collapse or constrain redundancy. Their effectiveness must be assessed using more than the training loss alone, including feature spread, effective rank, and downstream probes.
* Masked prediction: A masked autoencoder hides 75% of image patches and predicts their pixel values, with reconstruction loss applied only to the masked patches. In the standalone Cartpole experiment, its frozen-feature probe achieved mean R² of latexmath:[0.170\pm0.004] across three seeds. Reconstruction and state decodability are different measurements, and the method-family comparison is not a controlled ablation of the loss alone.
* Latent bottlenecks: The sweep found that Cartpole’s mean probe R² rose from approximately −0.008 at latexmath:[d=2] to latexmath:[0.321] at latexmath:[d=64], then remained similar at latexmath:[d=256]. Cheetah’s probe R² continued rising to latexmath:[0.422] at latexmath:[d=256]. The smallest useful representation depends on the task and the measured plateau; it cannot be determined simply by counting physical state variables.
* Prediction over time: CPC uses a causal GRU context and multi-horizon InfoNCE to identify the correct future latent among candidates. Top-1 retrieval reached 95.0%, 94.1%, and 92.4% at horizons one, two, and three, respectively, against a 3.5% query-weighted in-batch chance level. These results demonstrate future-latent identification under the tested protocol, not complete state recovery, action-conditioned dynamics, stable physical rollouts, or planning utility.
* Assembling the encoder: A common `+encode(obs)+` and `+update(state, obs)+` interface connects the learned visual encoder to the Chapter 1 agent loop, while dynamics and reward remain to be implemented. Across all these methods, the governing principle is that a representation-learning objective is a specification of what information the representation is paid to keep.
== Appendix A: InfoNCE bound and gradient details
This appendix contains the algebra moved out of §3.3 to preserve the main chapter’s teaching flow while retaining the full derivation. It uses the same notation as Table 3.1. The claims are conditional on the sampling assumptions described in §3.3; the recorded trajectory batch is not an ideal independent-negative sampler.

=== Where the bound comes from

*Sidebar: A proof of the InfoNCE bound*

Suppose one of latexmath:[K+1] candidates is drawn from the conditional distribution latexmath:[p(b\mid a)], while the others are drawn independently from the marginal distribution latexmath:[p(b)]. Let latexmath:[r_j=p(b_j\mid a)/p(b_j)], and let latexmath:[S=\sum_{j=0}^{K}r_j].

*Step 1: The best possible classifier.* Given the anchor and candidates, Bayes’ rule assigns candidate latexmath:[j] probability latexmath:[r_j/S] of being the positive. Any classifier latexmath:[q_j] incurs cross-entropy at least as large as this true posterior:

[latexmath]
++++

\mathcal{L}(f)\ge
-\mathbb{E}\log\frac{r_m}{S}.
++++

*Step 2: Express that cross-entropy using mutual information.* The expected log likelihood ratio of a positive pair is latexmath:[I(a;b)], so the expression on the right is

[latexmath]
++++

\mathbb{E}\log S-I(a;b).
++++

*Step 3: Bound the remaining term.* Under the reference distribution where all latexmath:[K+1] candidates are independently sampled from the marginal latexmath:[p(b)], write latexmath:[T=S/(K+1)]. The actual candidate-set distribution has density latexmath:[T] relative to this reference distribution, so

[latexmath]
++++

\mathbb{E}[\log S]
= \log(K+1)+\mathbb{E}_0[T\log T]
\ge \log(K+1),
++++

because latexmath:[\mathbb{E}_0[T]=1] and latexmath:[t\log t] is convex, so Jensen’s inequality makes latexmath:[\mathbb{E}_0[T\log T]] nonnegative. Combining the three steps yields

[latexmath]
++++

\mathcal{L}_{\mathrm{InfoNCE}}
\ge \log(K+1)-I(a;b),
++++

which rearranges to equation 3.6.

The gradient can also be made precise. The result in equation 3.7 separates attraction toward the positive from repulsion by negatives. For an anchor latexmath:[i], define the score latexmath:[s_{ij}=\operatorname{sim}(z_i,z_j)]. Differentiating the cross-entropy in equation 3.5 with respect to a candidate score gives

[latexmath]
++++

\frac{p_i(j)-\mathbf{1}[j=i^+]}{\tau},
++++

where latexmath:[\mathbf{1}[\cdot]] equals one if its condition is true and zero otherwise. Applying the chain rule yields the gradient with respect to the anchor representation:

For cosine similarity,

[latexmath]
++++

\frac{1}{\lVert u\rVert_2}
\left(
\frac{v}{\lVert v\rVert_2}
-\operatorname{sim}(u,v)
\frac{u}{\lVert u\rVert_2}
\right).
++++

The gradient is perpendicular to latexmath:[u], so each score’s local update changes the direction of the vector rather than its length to first order.

=== Why this bound is not a physical-state guarantee

The lower bound concerns mutual information shared by paired-view representations under the stated sampling assumptions. It does not establish that cart position, angle, velocity, or an action-conditioned predictive state is linearly available. The data-processing inequality also limits shared information to information that survives the view-generation pipeline. These are the precise reasons the chapter follows the training objective with held-out state probes.
