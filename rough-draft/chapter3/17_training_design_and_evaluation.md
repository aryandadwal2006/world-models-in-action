# SSL training design, diagnostics and evaluation: the hidden architecture

The method name is only one part of a self-supervised learning system. This document expands the Cookbook's training-design and evaluation chapters into a checklist for understanding why a method behaves as it does.

## 1. The full objective is an interacting system

A practical SSL model can be represented as a set of coupled choices:

1. **Data distribution:** which examples and frequency/identity biases are present?
2. **View/corruption process:** what is transformed, masked, cropped, noised, shuffled or paired?
3. **Target construction:** label, candidate, prototype, teacher feature, pixel target, token ID or future latent?
4. **Encoder architecture:** convolutional model, ViT, sequence Transformer, audio frontend, recurrent or hybrid module?
5. **Projection or prediction modules:** is there a projector, predictor, decoder, codebook, clustering stage or teacher?
6. **Loss geometry:** softmax, sigmoid, cosine regression, MSE, cross-correlation, covariance penalty, clustering or conditional generation?
7. **Optimization dynamics:** gradient paths, stop-gradient, target EMA, optimizer, schedule, weight decay, normalization and batch statistics.
8. **Evaluation contract:** recognition, retrieval, dense localization, robustness, latent prediction, state sufficiency, rollout or planning?

A change to any one of these can alter the representation, even if the method retains the same name. An experiment comparing named SSL methods is only controlled if relevant differences are isolated or the comparison is clearly framed as whole-recipe benchmarking.

## 2. Augmentation defines the invariance prior

Let A denote a stochastic augmentation distribution. Contrastive and many bootstrap methods learn the relation generated by pairs \(v_1,v_2\sim A(x)\). An augmentation becomes a prior about task irrelevance: transformed attributes are encouraged not to dominate the learned representation.

In image classification, a crop may preserve class identity while removing the exact position of an object. For world modeling, position can be a state variable. A color shift might be a nuisance in one camera domain and erase a colored tracking marker in another. Heavy blur can aid semantic invariance but remove thin geometry. The correct recipe must follow the downstream state contract, not a generic “strong augmentation wins” rule.

Audit every augmentation:
- Is its transformation label accidental or correlated with the target?
- Does it preserve the physical identity and action outcome we care about?
- Could it remove an object, boundary or interaction?
- Does it produce a positive pair that should be equivalent for the intended downstream task?
- Is it consistent with the target domain's observation process?

## 3. Batch size, negatives and distributed learning

For SimCLR-style objectives, batch composition controls the candidate dictionary. If local batch size is B per worker and there are W workers, the effective batch may be \(B_{\mathrm{eff}}=WB\) if embeddings are gathered across workers before loss computation. If the gather does not preserve gradient flow, the gradients and objective may differ from the intended global-batch contrastive loss.

Larger batches provide more diverse negative candidates and make some difficult negatives more likely to appear, but increase memory, communication and compute. The same nominal batch size is not equivalent if one implementation gathers across devices and another computes only local negatives.

Learning-rate scaling is a recipe heuristic, not a theorem. Common linear scaling uses \(\eta\propto B_{\mathrm{eff}}\); other recipes use square-root scaling for certain settings. The valid schedule depends on optimizer, warmup, architecture, batch statistics and training duration. The dossier should report exact conventions rather than presenting one rule as universal.

MoCo changes this problem by maintaining a queue, but its keys come from previous encoder states. Contrastive performance therefore depends not only on negative count but also key staleness and target-encoder momentum.

## 4. Projector and backbone are different representations

Let h=f(x) be the backbone output and z=g(h) be a projector output used by the loss. The projector creates an optimization space where the SSL objective's invariance, contrastive or redundancy constraints are applied.

Do not assume:
- z and h have the same dimension;
- z and h have the same covariance/rank;
- the output used for pretraining is the feature used downstream;
- a collapse diagnostic at the projector output automatically certifies the backbone;
- wider projectors always help, or that eliminating a projector never changes training.

Measure singular values and effective rank at both h and z. If a method's paper discards the projector for transfer, this is a part of the method definition, not a minor implementation detail.

## 5. Teacher EMA and predictor: independent roles

EMA target update is

\[
\xi_t=m\xi_{t-1}+(1-m)\theta_t.
\]

It smooths the target across time; for a high m, the target lags the online model. It can stabilize self-distillation but does not by itself enforce nonzero feature variance or full rank.

A predictor q introduces a map \(q(z_{\mathrm{online}})\) that learns to match target \(z_{\mathrm{target}}\). It changes the regression problem and optimization field. BYOL uses both a predictor and EMA target; SimSiam uses a predictor and stop-gradient target without EMA; DINO predicts distributions and updates a teacher; Barlow Twins and VICReg instead use explicit cross-view statistical constraints and do not rely on the same teacher-target mechanism.

These mechanisms must not be collapsed into one vague explanation that “asymmetry prevents collapse.” State exactly where the gradient flows and how target parameters are updated.

## 6. Collapse diagnostics: constant and dimensional collapse

### Constant collapse

All inputs map to the same feature vector. A constant representation can satisfy pure invariance regression because two views agree exactly. This is the simplest counterexample to the claim that view agreement alone guarantees useful features.

### Dimensional collapse

Representations vary across inputs but occupy a lower-dimensional subspace than their nominal feature dimension. For example, a 2048-dimensional feature matrix can have only a few dominant singular values. Per-dimension variance floors can detect dimensions with little spread, but correlated dimensions can still create low effective rank.

If a centered feature matrix is \(Z_c\in\mathbb{R}^{N\times d}\) and its singular values are \(\sigma_1\geq\cdots\geq\sigma_r\), several diagnostics are possible:
- numerical rank with a declared threshold;
- effective rank from the normalized singular-value distribution;
- entropy \(H(p)=-\sum_i p_i\log p_i\), where \(p_i=\sigma_i/\sum_j\sigma_j\) or a covariance-energy normalization (state which);
- singular value spectrum and its decay;
- per-dimension standard deviations;
- covariance/correlation matrix and feature norms;
- spread across data subgroups or augmentations.

These metrics answer different questions and depend on normalization. A singular-value entropy without a stated p_i convention is ambiguous. A representation with high rank is not necessarily semantic; it may preserve noise. Rank is a collapse diagnostic, not a sufficient evaluation objective.

## 7. Data balance and implicit distribution priors

Some instance-discrimination objectives spread representations to distinguish batch members. Prototype methods such as SwAV explicitly impose approximate assignment balance. The underlying data may have a long-tailed distribution, so balancing can favor frequent visual substructure or nuisance differences rather than rare semantic categories.

Ask:
- Are classes or objects balanced?
- Is the dataset object-centric and curated, or in-the-wild?
- Does the objective impose a uniform prior over instances, neighbors or prototype use?
- Does nearest-neighbor selection over-represent common modes?
- Are evaluation metrics macro-averaged or dominated by frequent classes?
- Are data curation and filtering part of the reported contribution?

DINOv2's dataset curation and current large-scale foundation model recipes show that data collection is not an incidental detail. It is part of the system.

## 8. Evaluation: a probe answers a particular question

### k-NN

Freeze features and assign a test example using labels of nearest training embeddings. This evaluates local neighborhood structure under a chosen metric and k. It is relatively simple but depends on representation normalization, k, temperature/weighting and the sampled training set.

### Linear probe

Freeze the backbone and train a linear classifier. High performance shows that class information is linearly accessible with the chosen protocol. It does not prove:
- all relevant information is present;
- unmeasured variables are preserved;
- the representation is Markov sufficient;
- features are causal or invariant under deployment shift;
- a dynamics model or planner can use them.

A linear probe can also be sensitive to normalization, selected layer, class balance, augmentations at evaluation time, optimizer and training duration. The protocol must be specified.

### MLP probe

A nonlinear probe can reveal information that is present but not linearly accessible. But greater capacity may memorize or overfit, making the result less pure as a measure of representation geometry. Compare linear and nonlinear probes rather than treating one as universal.

### Fine-tuning

Fine-tuning measures the combination of pretrained features and their adaptability under a labeled downstream budget. Its outcome depends on which parameters are unfrozen, layer-wise learning rates, schedule, augmentation and amount of label data. It is not directly comparable to frozen linear probe results.

### Label-free measures and visual inspection

Nearest-neighbor retrieval, feature similarity across views, rank/collapse checks, reconstruction error and feature visualizations are useful diagnostics but are proxies. They should not replace downstream evaluation. A PCA visualization can show structure, but cannot certify semantic segmentation, physical dynamics or robustness.

## 9. Evaluation for a world model is stricter than recognition

World-model tasks require separate tests:
1. **State-variable accessibility:** can the representation support decoding relevant position, velocity, contact, occlusion and scene variables on held-out data?
2. **State aliasing:** do two observations with the same representation have different futures or reward under the same action?
3. **Temporal consistency:** does a sequence of representations retain changes necessary for prediction?
4. **Action conditioning:** do different actions produce distinguishable predicted futures where physics says they should?
5. **Rollout quality:** does multi-step prediction remain coherent rather than only matching one-step targets?
6. **Intervention/generalization:** do dynamics predictions hold under held-out actions, object configurations or domains?
7. **Planning performance:** does planning on model predictions improve actual task outcomes after accounting for model exploitation?
8. **Representation robustness:** does the encoder remain valid when augmentation assumptions, camera/viewpoint and background change?

A high image-classification score is one signal about semantic features; it is not a certificate for any of these claims.

## 10. Dense and spatial features

Global image classification tends to reward features that summarize whole-image categories. Detection and segmentation need local features aligned to image regions. Methods such as DenseCL, PixPro, VICRegL, SelfPatch, Leopart, iBOT and more recent DINO/JEPAs introduce local correspondence, patch-level targets or dense feature objectives.

There is no universal guarantee that the best global representation is the best local representation. Crops change patch locations; correspondence may be uncertain; multiple objects overlap; spatial invariance can remove location information that a dense task needs. Evaluation should therefore include dense tasks or geometry-sensitive probes when localization matters.

## 11. Multimodal positives and weak supervision

CLIP and ALIGN use image-text pairings. SigLIP changes the cross-modal loss from batchwise softmax to pairwise sigmoid. The data pairing itself is a training signal, even when it is not a manually assigned class label. Caption noise, duplicate concepts, unequal frequency and missing entities affect what the joint representation learns.

Likewise, speech methods use raw audio sequences but can construct quantized or cluster-derived units. “Unlabeled” does not mean the training objective has no structure; it means the target is constructed without a conventional human annotation of the target task.

## 12. Reproducibility and report checklist

Every experiment should report:
- paper/version and official implementation revision;
- dataset source, filtering, split and licensing;
- model/backbone and feature layer used downstream;
- augmentation/corruption pipeline;
- projector/predictor/decoder architecture;
- exact loss equation and reduction;
- negative set, queue or target-generation algorithm;
- EMA rate/schedule, stop-gradient and normalization locations;
- effective batch size and global negative behavior across devices;
- optimizer, learning rate, warm-up, weight decay, epochs/steps and seeds;
- compute hardware, precision, checkpoint and total wall-clock time;
- collapse diagnostics at both backbone and projector output;
- exact downstream evaluation protocol and uncertainty.

These details are part of the scientific method description, not clutter to be omitted if the reader is expected to reproduce the work.
