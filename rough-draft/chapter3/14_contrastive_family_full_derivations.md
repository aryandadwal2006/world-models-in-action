# Contrastive family: full first-principles derivations and variants

This file expands the contrastive section beyond the reader-facing chapter. It develops the candidate-classification derivation and records the architecture choices that differentiate major members of the family.

## 1. Start with a relation, not a loss name

Let \(x\sim p_X\) be a source observation. A stochastic augmentation kernel \(a(v\mid x)\) generates a view \(v\). Two independent views of the same source are sampled as \(v_1\sim a(\cdot\mid x)\) and \(v_2\sim a(\cdot\mid x)\). A shared encoder \(f_\theta\) produces \(h=f_\theta(v)\), and an optional projection head \(g_\phi\) produces \(z=g_\phi(h)\).

The learning assumption is not that \(v_1=v_2\) or that they are identical in every property. It is that the relationship between them should be discoverable in the representation space, and that some variations induced by augmentation should be ignored. This relation is generated by the augmentation and pairing process.

If an augmentation removes a relevant state variable, no choice of optimizer can recover it from the target label if the objective explicitly rewards invariance to it. This is an information-design issue upstream of gradient descent.

## 2. From candidate identification to softmax cross-entropy

For a query representation \(z_q\), define K candidate representations \(z_1,\ldots,z_K\), exactly one of which is designated positive with index \(y\). Let the score be \(s_k=s(z_q,z_k)\). The temperature-scaled logit is \(a_k=s_k/\tau\), with \(\tau>0\).

The model assigns candidate probability

\[
p_\theta(k\mid q,\{z_j\})=\frac{\exp(a_k)}{\sum_{j=1}^{K}\exp(a_j)}.
\]

The desired target distribution is one-hot at y. Cross-entropy is therefore

\[
\mathcal{L}(q)=-\sum_{k=1}^K\mathbf 1[k=y]\log p_\theta(k\mid q)
=-\log p_\theta(y\mid q).
\]

Substitute softmax:

\[
\mathcal{L}(q)=-a_y+\log\sum_{j=1}^K\exp(a_j).
\]

Differentiate with respect to an arbitrary logit \(a_k\). Since the derivative of log-sum-exp is softmax,

\[
\frac{\partial \mathcal{L}}{\partial a_k}
=p_\theta(k\mid q)-\mathbf 1[k=y].
\]

By the chain rule,

\[
\frac{\partial\mathcal{L}}{\partial s_k}
=\frac{p_\theta(k\mid q)-\mathbf 1[k=y]}{\tau}.
\]

This proves three things. First, the positive's logit gradient is negative unless its probability is already one, so gradient descent tends to raise its score. Second, each negative's gradient is positive, so descent tends to lower its score. Third, the size of a negative's gradient is its predicted probability. A high-similarity negative gets more gradient than a candidate that is already easy to reject. There is no fixed equal “push” for every negative.

This derivation is independent of the mutual-information interpretation. InfoNCE can be understood and implemented as candidate classification without assuming that every implementation maximizes a well-defined mutual-information bound.

## 3. SimCLR: the exact candidate set

For a batch of B underlying images, draw two augmented views per source. There are 2B view embeddings. For anchor index i, the positive index \(p(i)\) identifies the other view from the same source. Exclude i from the denominator. Then

\[
\ell_i=-\log
\frac{\exp(s(z_i,z_{p(i)})/\tau)}
{\sum_{a=1}^{2B}\mathbf 1[a\ne i]\exp(s(z_i,z_a)/\tau)}.
\]

The per-anchor denominator contains \(2B-1\) candidates: one positive and \(2B-2\) negatives. Averaging over all 2B anchors gives the symmetric NT-Xent objective.

A recurring notation trap is that some papers call batch size the number of source images, while others describe the number of views; some use K for negatives and others for total candidates. Write the actual sum and count rather than trusting a letter without a definition.

### Why SimCLR uses a projector

Let \(h_i=f_\theta(v_i)\) and \(z_i=g_\phi(h_i)\). The loss is applied to z, but downstream tasks often use h. These representations can have different geometry. The projector permits the training objective to discard or reshape information in its own space without requiring the backbone feature to satisfy all loss-space constraints in the same way.

One must therefore distinguish:
- backbone feature dimension and rank;
- projector output dimension and rank;
- where normalization is applied;
- which tensor enters the loss;
- which tensor is reused downstream.

A high-quality projector output does not prove the backbone itself is free from dimensional collapse. The reverse cannot be assumed either. Diagnose both separately.

### The augmentation contract

SimCLR's commonly used visual recipe combines random resized cropping with other color and appearance transformations. These were selected for visual recognition, not for all possible world-model tasks. An augmentation should be audited against the variables of interest:
- crop: can remove object identity, relative geometry, contact state or scene context;
- horizontal flip: can erase chirality, directional labels or handedness;
- color jitter/grayscale: can erase color identity or material cues;
- blur: can erase fine texture or thin boundaries;
- temporal sampling: can remove motion direction or turn velocity into an ambiguous static image.

An augmentation may also create a shortcut if it is correlated with source or target labels. “Stronger augmentation” is not universally better.

## 4. The mutual-information connection, with assumptions visible

Let a positive pair \((X,Y)\) be drawn from joint distribution \(p(x,y)\). A negative \(Y'\) is drawn independently from marginal \(p(y)\). An ideal binary or K-way discriminator is related to the density ratio \(p(y\mid x)/p(y)\). Since

\[
\log\frac{p(y\mid x)}{p(y)}
=\log p(x,y)-\log p(x)-\log p(y)+\log p(x),
\]

the log density ratio is connected to pointwise mutual information; averaging that log ratio under the joint gives \(I(X;Y)\).

The standard K-candidate InfoNCE result, with the paper's candidate sampling convention, gives a bound commonly written

\[
I(X;Y)\ge \log K-\mathcal{L}_{\mathrm{NCE}}.
\]

Do not omit these caveats:
1. The positive and negative samplers must match the assumptions in the derivation.
2. K must be defined: candidate count and negative count conventions differ.
3. The right-hand side cannot exceed \(\log K\), since cross-entropy is nonnegative.
4. The bound is not a theorem that a representation is sufficient for a control policy.
5. A high estimate can be driven by nuisance dependence between augmented views, and a downstream-relevant distinction may not be the easiest dependence to preserve.

Other explanations of contrastive objectives emphasize alignment and uniformity or connections to dependence measures such as HSIC. These perspectives complement each other; the chapter should not imply that mutual information is the unique complete explanation of contrastive training.

## 5. False negatives and candidate semantics

A contrastive objective classifies a candidate as positive or negative according to the pair-generation protocol. It does not know the ground-truth semantic equivalence relation unless that information is encoded in the sampling process.

Example: an anchor image of a red bicycle and a negative image of a blue bicycle may be treated as distinct instances. If the downstream task is object-category recognition, the negative may be semantically positive; if the task is exact scene-state representation, the distinction may be important. Therefore “false negative” is defined relative to an intended equivalence relation, not absolutely.

Potential responses include larger or curated positive sets, supervised contrastive learning when class labels are available, nearest-neighbor positives, debiased contrastive objectives, excluding likely false negatives, or changing to a non-contrastive loss. Each introduces its own assumptions and costs.

## 6. MoCo: queue, key encoder, and stale representations

MoCo separates a query encoder \(f_{\theta_q}\) from a key encoder \(f_{\theta_k}\). For current query \(q\) and positive key \(k^+\), score them against a positive plus a queue of negative keys \(k_1,\ldots,k_M\):

\[
\mathcal L_{\mathrm{MoCo}}
=-\log\frac{\exp(q^\top k^+/\tau)}
{\exp(q^\top k^+/\tau)+\sum_{j=1}^M\exp(q^\top k_j/\tau)}.
\]

The key encoder uses an exponential moving average:

\[
\theta_k^{(t)}=m\theta_k^{(t-1)}+(1-m)\theta_q^{(t)}.
\]

An encoded key enters a FIFO queue; the oldest keys are removed when the queue capacity is exceeded. This provides many candidates without storing the full dataset's feature tensor or requiring the entire dictionary in one minibatch.

### What the EMA equation means

Expanding the recurrence,

\[
\theta_k^{(t)}
=(1-m)\sum_{r=0}^{t-1}m^r\theta_q^{(t-r)}+m^t\theta_k^{(0)}.
\]

The target is an exponentially weighted history of online parameters. Larger m yields slower target drift and more stale alignment to earlier training states. The EMA smooths changes; it is not an explicit covariance or variance constraint.

### The queue trade-off

- Increasing queue size increases the number and diversity of candidates.
- Older keys correspond to older parameter values.
- A slowly changing key encoder reduces but does not erase the mismatch.
- False negatives remain: a queue does not know semantic classes.
- The queue adds memory and implementation complexity.

MoCo v2 should be described as a strong recipe refinement, including stronger augmentation and a projection head. MoCo v3 is an empirical SSL recipe for vision transformers and altered training details. They are related but not identical to the original convolutional MoCo mechanism.

## 7. CPC as a historical bridge

Contrastive Predictive Coding defines latents \(z_t=f(x_t)\) and context \(c_t=g(z_{\leq t})\). For future offset k, a compatibility score such as \(s_k(c_t,z_{t+k})=z_{t+k}^{\top}W_kc_t\) makes the future representation a candidate-classification target. The correct future latent is ranked against distractor candidates using an InfoNCE-style loss.

CPC's conceptual contribution is that the target can live in latent space and can be temporally separated from the context. This is more flexible than pixel reconstruction. But the usual CPC objective does not itself make the predictor action-conditioned. Candidate retrieval for future latents is not the same as generating a recursive rollout of future states and not the same as testing a chosen action's consequences.

Its role in this Chapter 3 dossier is lineage: retain enough detail to explain why latent prediction mattered, then hand the deeper predictive-state discussion to the JEPA/world-model material.

## 8. Nearby variants to include in the landscape

### N-pair / triplet / metric learning

Triplet loss uses an anchor, positive and negative and enforces a margin between positive and negative distances. N-pair and multi-negative formulations use multiple competitors. These are ancestors or relatives of modern contrastive SSL, not the same objective under all conventions.

A common triplet form is

\[
L_{\mathrm{triplet}}=\max\{0, d(z_a,z_p)-d(z_a,z_n)+\alpha\},
\]

where \(\alpha>0\) is a margin. If positive and negative distances already differ by at least the margin in the desired direction, the term is zero. Unlike softmax contrastive losses, this objective can ignore easy triplets after the margin is satisfied.

### Supervised contrastive learning (SupCon)

SupCon uses labels to define all or multiple same-class samples as positives for an anchor. It is not strictly label-free SSL, but it is important as a comparison: adding label-defined positives changes the equivalence relation and reduces the pressure to discriminate same-class instances from each other. In a hybrid training system, SupCon can be an auxiliary task when labels are available.

### NNCLR

Nearest-neighbor contrastive learning (NNCLR) selects a nearest-neighbor feature as a positive target, rather than only taking another augmented view of the same instance. This can expand the positive relation to semantically related examples and lessen dependence on instance identity. It also imports nearest-neighbor errors: false matches can reinforce incorrect equivalences. The memory bank, normalization and exact neighbor-selection mechanism must be checked in the original paper and implementation.

### Debiased contrastive learning and negative sampling

Methods such as Debiased Contrastive Learning alter the contribution of possible same-class negatives or the estimator itself. Hard-negative mining instead increases the weight or frequency of difficult candidates. These are not identical fixes: one attempts to correct a sampling bias; the other changes which candidates dominate training. An InfoNCE denominator already emphasizes high-probability negatives, but only among those sampled.
