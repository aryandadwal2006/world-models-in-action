# 3.8 Assembling the encoder

#### A common encoder interface

The current repository implements the shared interface in `worldmodels/models/encoders.py`. The Encoder class wraps a backbone, such as the ConvEncoder trained in Section 3.3. It exposes two methods:

`encode(obs)` maps an observation to its latent representation.

`update(state, obs)` processes the observation and returns the updated agent state.

The second method can operate in either of two ways. Without a recurrent layer, it simply returns the encoded observation. With a recurrent layer, it passes the representation and previous recurrent state through a GRU cell. On the first call, when no previous state exists, it initializes the hidden state to zeros.

**Listing 3.13 — The encoder interface**

Source: `worldmodels/models/encoders.py`. The excerpt below is taken from the canonical implementation.

```python
class Encoder(nn.Module):
    """Unified encoder interface used by the Chapter 1 agent loop."""

    def __init__(
        self,
        backbone: nn.Module,
        recurrent_hidden_dim: Optional[int] = None,
    ) -> None:
        super().__init__()
        self.backbone = backbone
        self.recurrent_hidden_dim = recurrent_hidden_dim
        if recurrent_hidden_dim is not None:
            latent_dim = getattr(backbone, "latent_dim", 16)
            self.gru_cell = nn.GRUCell(
                latent_dim, recurrent_hidden_dim
            )
        else:
            self.gru_cell = None

    def encode(self, obs: torch.Tensor) -> torch.Tensor:
        if obs.ndim == 3:
            obs = obs.unsqueeze(0)
        return self.backbone(obs)

    def update(
        self,
        state: Optional[torch.Tensor],
        obs: torch.Tensor,
    ) -> torch.Tensor:
        z = self.encode(obs)
        if self.gru_cell is None:
            return z
        if state is None:
            state = torch.zeros(
                z.shape[0],
                self.recurrent_hidden_dim,
                device=z.device,
                dtype=z.dtype,
            )
        return self.gru_cell(z, state)
```

The wrapper keeps the representation-learning architecture separate from the agent's interface. The backbone determines how observations are encoded. The optional GRU cell determines how successive encodings are combined into a persistent hidden state.

The word state in this interface refers to the encoder's recurrent hidden state, not the simulator's ground-truth physical state. During normal operation, the agent does not receive qpos or qvel from the simulator. It receives the rendered observation and carries its own internal state between calls.

The wrapper also does not dictate how the encoder was trained. A different compatible backbone can be substituted without changing the calls made by the agent loop. The interface is small, but it creates an important separation: training objectives can change while the rest of the agent continues to consume an observation and an updated internal state.

#### Verifying the contract

The repository's ch03/12_assemble_encoder.py runner checks this interface using a saved contrastive encoder checkpoint. It loads the encoder with a latent dimension of 16 and wraps it with a recurrent hidden dimension of 32. The script then processes ten validation frames in order, passing the previous hidden state into each subsequent update.

The expected recurrent-state shape is `(1, 32)`. The committed output in ch03/results/table_03_06_synthesis.json records that shape and the ten frames tested.

This is an interface smoke test, not an evaluation of representation quality. It verifies that the checkpoint loads, the encoder processes observations, and the recurrent-state contract holds for the tested sequence. It does not establish that the representation is sufficient for control, that the recurrent state captures all relevant history, or that the assembled agent can act successfully in the environment.

The interface therefore completes a software contract, not the scientific contract from Chapter 2. Whether the representation is useful depends on the measurements from the preceding sections and on what the later dynamics and reward components require.

#### What each objective pays to preserve

The experiments show why a common interface does not imply that all encoders learn equivalent representations. The objective used during training determines which relationships are rewarded. Table 3.6 summarizes the central trade-off from this chapter.

**Table 3.6 — Representation objectives and their trade-offs**

| Objective | Paid to keep | May discard | Invited failure |
| --- | --- | --- | --- |
| Pretext tasks | Task-defined structure | Variables irrelevant to the pretext | Shortcut features |
| Contrastive (NT-Xent) | Structures preserved across views | Information removed by augmentation | False negatives and aggressive invariance |
| Non-contrastive methods | Invariant, non-collapsed coordinates | Redundant coordinates | Collapse if the anti-collapse mechanism fails |
| Masked autoencoding | Information useful for reconstruction | Details irrelevant to pixel recovery | Capacity spent on predictable pixels |
| Temporal CPC | Information useful for future prediction | Unpredictable innovations | Action-unconditioned prediction ceiling |

The table is not a ranking. Each row describes the direct pressure imposed by a family of objectives, together with a corresponding risk. Whether a particular model actually suffers that failure must be measured.

Pretext tasks define their own prediction target. That target can create useful supervision from the structure of observations, but it can also reward shortcuts that solve the pretext without preserving the information needed downstream.

Contrastive learning pays for agreement across the views constructed by the augmentation pipeline. This is useful when the chosen transformations preserve task-relevant distinctions. It becomes a problem when an augmentation removes information the agent needs, or when different frames that look similar become false negatives.

Non-contrastive methods demonstrate that negatives are not the only way to prevent collapse. SimSiam, BYOL, Barlow Twins, and VICReg use different mechanisms to constrain the learned representation. Those mechanisms introduce their own design choices, and the reduced-scale experiments in this chapter do not establish a universal ranking of the methods.

Masked autoencoding pays for reconstructing missing pixel content. It may devote capacity to background or other predictable image details that do not make physical variables easy to decode. The Cartpole experiment found that reconstruction quality and state-probe quality are distinct measurements.

CPC changes the target from reconstructing an observation to identifying its future representation from a context. The retrieval experiment shows that the correct future latent can be identified at high rates within the tested candidate batches. Its state probes remain weak for velocity, and the model receives no action input. Future-latent identification alone is therefore not a guarantee of a complete predictive state.

The common pattern is that an objective cannot be judged solely by whether its loss decreases. We need to examine what its representation preserves, what it discards, and whether those properties match the agent's requirements.

#### Checking the Chapter 2 contracts

The measurements in this chapter give partial evidence about the contracts introduced in Chapter 2. They do not settle every question about the learned state. The following checklist separates what was measured from what remains unverified.

**Chapter 2 contract check**

- **Sufficiency: preserve information relevant to the task** Evidence: Frozen-feature linear probes measure whether physical state variables are linearly recoverable. Position variables are often more decodable than velocities. The MAE, contrastive, and VICReg comparison also shows that results differ across complete model configurations. Remaining limit: A linear probe measures explicit linear decodability, not all information present in a representation. These experiments do not demonstrate successful control or planning.
- **Minimality: avoid retaining unnecessary detail** Evidence: The latent-dimension sweep measures probe performance from $d=2$ through $d=256$. Cartpole approaches a plateau between $d=64$ and $d=256$, while Cheetah performance is still rising at $d=256$. Remaining limit: The sweep does not measure mutual information directly, prove a globally minimal representation, or establish a plateau for Cheetah.
- **Aliasing: distinguish situations that require different predictions or actions** Evidence: The aliasing diagnostic compares single-frame and stacked-frame representations. Mean cart-velocity R² changes only from approximately 0.006 to 0.009, while pole-angular-velocity R² becomes slightly worse, from approximately −0.367 to −0.375. Remaining limit: Under the tested resolution, augmentation, architecture, and budget, stacking two frames did not reliably recover velocity. This does not prove that temporal information can never resolve the ambiguity.
- **Markov property and predictive state: retain history relevant to the future** Evidence: CPC's GRU context identifies matching future latents with top-1 retrieval of approximately 92%–95% across the three tested horizons. The mean next-state probe R² is numerically higher for the context than for the static encoder. Remaining limit: The context does not make every physical variable linearly decodable. The experiment does not establish conditional independence from earlier history, accurate recursive physical prediction, or stable long-horizon rollouts.
- **Action-conditioned dynamics: predict outcomes in relation to actions** Evidence: The CPC experiment measures future-latent identification using sequences collected under a random policy. Remaining limit: The model receives frames but not actions. This experiment does not evaluate action-conditioned prediction or establish planning utility.
