# 3.5 Masked prediction

### 3.5.1 From masked words to masked patches

BERT trains a language model by hiding selected tokens and asking it to predict them from the surrounding context. The targets are the identities of the missing tokens, not a human-written label for the whole sentence. The model learns from the structure already present in the text.

A masked autoencoder $MAE$ applies a related idea to images. It divides an image into patches, hides a random subset, and predicts the missing pixel values from the visible patches. The training target comes directly from the input image. No class label, action, reward, or physics state is required.

The masking ratio matters. If only a few patches are hidden, nearby visible pixels may make reconstruction relatively easy. Hiding a large fraction of the image creates a more demanding prediction task: the model must use the remaining patches and their relationships to reconstruct the missing content. The original MAE work found that a high masking ratio, such as 75%, could produce a useful self-supervised task at scale. That result motivates our choice; it does not establish that 75% is optimal for every dataset or architecture.

Our experiment uses $64\times64$ RGB frames from the Control Suite's Cartpole Balance task. Each image is divided into an $8\times8$ grid, giving 64 patches. With a masking ratio of 75%, the encoder sees 16 randomly selected patches during training. The decoder predicts all 64 patches, but only the masked patches contribute to the loss.

This is an asymmetric architecture. The encoder processes the visible patches without carrying a placeholder token for every hidden patch. The decoder receives the encoded visible patches, inserts learned mask tokens into the missing positions, restores the original order, and predicts the pixel values. This division keeps the encoder's training input smaller than the full image's patch sequence.

There is an important boundary to the analogy with language. A rendered physics frame is far simpler than a natural image, and our images contain a stable background. Reconstructing a Cartpole frame is not the same as reconstructing the physical state that generated it. In particular, a single image need not reveal velocity. The experiment tests what this compact MAE learns under its particular data, architecture, and training budget.

### 3.5.2 Building a masked autoencoder

The first operation is to turn an image into a sequence of patches. For a batch of images, the resulting tensor has shape

$$
P\in\mathbb{R}^{B\times N\times D},
$$

where $B$ is the batch size, $N=64$ is the number of patches, and $D=8\times8\times3=192$ is the number of pixel-channel values in each flattened patch.

A learned linear layer embeds each patch into a 64-dimensional token. Positional embeddings distinguish the patches' locations. The model then samples a different random mask for each image in the batch. It retains 16 tokens and sends only those tokens through the encoder.

**Listing 3.10 — Masking and the MAE forward pass**

Source: `worldmodels/models/masked_autoencoder.py`; reconstruction loss: `worldmodels/losses/reconstruction.py`. This is a shortened excerpt; patchification and decoder helpers remain in the canonical module.

```python
def forward_encoder(self, x: torch.Tensor):
    patches = self.patchify(x)
    tokens = self.patch_embed(patches) + self.encoder_pos_embed
    b, n, d = tokens.shape
    len_keep = int(n * (1.0 - self.mask_ratio))

    noise = torch.rand(b, n, device=x.device)
    ids_shuffle = torch.argsort(noise, dim=1)
    ids_restore = torch.argsort(ids_shuffle, dim=1)
    ids_keep = ids_shuffle[:, :len_keep]
    visible = torch.gather(
        tokens, 1, ids_keep.unsqueeze(-1).expand(-1, -1, d)
    )

    mask = torch.ones(b, n, device=x.device)
    mask[:, :len_keep] = 0.0
    mask = torch.gather(mask, 1, ids_restore)

    encoded_visible = self.encoder_transformer(visible)
    z = encoded_visible.mean(dim=1)
    return z, encoded_visible, mask, ids_restore


def forward(self, x: torch.Tensor):
    patches = self.patchify(x)
    _, encoded_visible, mask, ids_restore = self.forward_encoder(x)
    pred_patches = self.forward_decoder(encoded_visible, ids_restore)
    loss = masked_mse_loss(patches, pred_patches, mask)
    return loss, pred_patches, mask
```

The random values in noise define a permutation of the patch positions. ids_keep selects the visible tokens, while ids_restore records how to put the visible tokens and mask tokens back into their original order for decoding. The mask uses 1 for a hidden patch and 0 for a visible patch. These details are important: a decoder must know which predicted patch belongs in which image location.

The training objective is the mean squared error over masked patches only. Let $P_{bi}$ denote patch $i$ from image $b$, let $\hat P_{bi}$ be its prediction, and let $M_{bi}$ equal 1 if that patch was masked and 0 otherwise. With $D$ pixel-channel values per patch, the loss is

$$
\frac{
\displaystyle\sum_{b=1}^{B}\sum_{i=1}^{N}
M_{bi}\left[
\frac{1}{D}\sum_{j=1}^{D}
(P_{bij}-\hat P_{bij})^2
\right]
}{
\displaystyle\sum_{b=1}^{B}\sum_{i=1}^{N}M_{bi}
}.
\tag{3.18}
$$

The denominator counts masked patches, so each hidden patch contributes its mean pixel-channel error. Visible patches do not contribute to the loss, even though the decoder produces predictions for them too. This matches the implementation in masked_mse_loss.

The physics states collected from the simulator do not enter this objective. They remain available for evaluation, including the linear-probe tests used elsewhere in the chapter. The only training target here is the hidden image content.

### 3.5.3 Reconstruction versus representation

A reconstruction loss measures how well the model rebuilds its input. A state probe asks a different question: how much information about the simulator's state can be recovered by a linear map from the learned representation? Good reconstruction does not guarantee a strong state representation, just as a strong state probe does not guarantee pixel-accurate reconstruction.

Consider the target in equation 3.18. The error is measured across the pixels of every masked patch, including patches containing the floor and background. These pixels are part of the image and therefore part of the objective, even when their appearance says little about the cart's position or the pole's angular velocity. The encoder can be rewarded for retaining information that helps reconstruct pixels without being equally rewarded for making every physical variable easy to decode linearly.

This is a hypothesis about the objective, not a conclusion that follows from the equation alone. We test it by examining reconstructions and measuring frozen-feature linear probes. The interpretation must remain bounded by the experiment: Cartpole frames at $64\times64$, the current patch-transformer architecture, a 75% masking ratio, and the stated training budget. These frames are far simpler than natural video, so this comparison does not establish a general ranking of reconstruction and contrastive methods.

#### The probe results

The standalone MAE experiment uses seeds 0, 1, and 2, 4,000 episode-stratified training frames, 1,000 validation frames, 15 epochs, a batch size of 64, and Adam with learning rate $10^{-3}$. Its probe uses the mean-pooled 64-dimensional encoder tokens. Across the three training seeds, the mean R² across the four Cartpole state variables is $0.170\pm0.004$. This is the result recorded in ch03/results/mae_metrics.json.

Its rendered geometry has $\pi$-periodic symmetry, so a static image cannot uniquely identify its absolute $2\pi$ angle. The position summary therefore averages the other position variables, and the velocity summary averages the task's velocity variables. The exclusion is part of the metric definition, not a discarded unsuccessful prediction.

The supervised row has a specific interpretation. The encoder and a prediction head were trained using privileged simulator-state labels, after which a separate linear probe was fit to frozen encoder features. The reported numbers belong to that separate probe, not to the trained prediction head's held-out score. The supervised reference is not a self-supervised method.

The per-variable results make the aggregates easier to interpret. The entries are mean R² ± standard deviation across the same three seeds and follow the state-vector order: Cartpole uses qpos[0], qpos[1], qvel[0], qvel[1]. Finger Spin uses qpos[0], qpos[1], qpos[2], qvel[0], qvel[1], qvel[2]. For Finger Spin qpos[2], the table reports a separate π-periodic score for visible orientation; absolute 2π angle remains unidentifiable from a static render. That score is displayed for completeness but excluded from the aggregate position score.

R² values below zero mean that the probe performs worse on the validation data than a constant predictor using the validation-target mean. In these runs, velocity is difficult to decode linearly across methods. The MAE's Cartpole position score is below those of the contrastive and VICReg representations in this comparison, while its Cartpole velocity score is less negative. On Finger Spin, MAE performs poorly on the second position variable and has negative velocity scores. No single aggregate tells the whole story.

These observations do not isolate the objective as the cause. MAE uses a patch-transformer encoder and decoder, and its evaluated feature vector is 64-dimensional. The contrastive and VICReg representations in this comparison use a convolutional backbone with a 16-dimensional latent representation. The supervised reference additionally uses privileged state labels during pretraining. Table 3.4 is therefore a method-family comparison under a stated budget, not a loss-only ablation. The measurements describe these complete configurations; they do not establish that masked reconstruction is inherently inferior to contrastive learning or VICReg.

The result is consistent with the chapter's central distinction: the training objective specifies what the encoder is directly rewarded for preserving. Masked prediction is useful when reconstructing hidden observations is the desired task, but pixel reconstruction alone does not ensure that the resulting features expose the physical state. World models ultimately need a representation that can support prediction and planning, not just one that can rebuild an image.

Before predicting in a representation space, we should ask how much representational capacity the state needs. The next section studies that question through latent bottlenecks.

3.6 Latent bottlenecks and compact state

A representation can fail in two opposite ways. It can discard information the agent needs, or it can retain much more detail than the task requires. Chapter 2 called the first problem a failure of sufficiency and the second a failure of minimality.

The dimension of a latent representation gives us one way to study this trade-off. A small latent vector limits the number of coordinates available to represent an observation. A larger vector gives the encoder more capacity, but that extra capacity does not guarantee that the encoder learns a more useful state.

This section treats dimensionality as an experimental question. We first introduce the information bottleneck as a way to reason about compression and relevance. We then train encoders at different latent dimensions and measure how much physical state a linear probe can recover.
