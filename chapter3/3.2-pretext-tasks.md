# 3.2 Pretext tasks: supervision from structure

A pretext task turns an unlabeled observation into a training example with a known target. The target comes from a transformation or relationship in the data, so we do not need a person to annotate each example.

Rotation prediction is a simple place to begin. It lets us construct the target explicitly, derive the loss from an ordinary classification problem, and then ask the central question of this chapter: does solving the pretext task require the encoder to preserve the information a world model needs?

#### Rotation prediction

Take a rendered cart-pole frame $x$. Rotate it by a multiple of 90 degrees and ask a network to predict which rotation was applied. We use four possible rotations: zero, 90, 180, and 270 degrees.

Let $r\in\{0,1,2,3\}$ be the rotation label, where $r$ counts quarter turns, and let $\rho_r(x)$ denote the corresponding rotated image. Starting with one frame gives us four training examples:

$$
\big(\rho_0(x),0\big),\quad
\big(\rho_1(x),1\big),\quad
\big(\rho_2(x),2\big),\quad
\big(\rho_3(x),3\big).
$$

The label is known because we chose the transformation. No human annotation is needed.

Our frames are square, so rotating by a quarter turn simply rearranges the pixels. We do not need to introduce padding or interpolate new pixel values. The target is therefore determined by the applied rotation, rather than by an artifact created at the image border.

Now we need a network that predicts the rotation. We already have an encoder $f_\theta$ from equation 3.1. Attach a classification head $g_\phi$, with parameters $\phi$, to map the representation to four scores:

$$
a(x')=g_\phi\!\left(f_\theta(x')\right).
$$

Here $x'$ is a rotated input, and $a_j(x')$ is the score, or logit, assigned to rotation class $j$. A logit is not yet a probability. We convert the four scores into probabilities using softmax:

$$
\frac{\exp(a_j(x'))}
{\sum_{m=0}^{3}\exp(a_m(x'))}.
$$

The four probabilities are nonnegative and sum to one. The model's task is to assign a high probability to the rotation that was actually applied.

How should we measure whether it does so? Suppose the correct label is $r$. Its predicted probability is $p_{\theta,\phi}(r\mid x')$. We penalize the network using the negative logarithm of that probability:

$$
-\log p_{\theta,\phi}(r\mid x').
$$

This is the familiar cross-entropy loss for a classification problem with one correct class. If the model assigns probability one to the correct answer, the loss is zero. If it assigns a very small probability to the correct answer, the loss is large.

We average this loss over the four rotations of each original frame, then over the training frames. The result is the rotation-prediction objective:

$$
-\mathbb{E}_{x}
\left[
\frac{1}{4}
\sum_{r=0}^{3}
\log p_{\theta,\phi}
\left(r\mid \rho_r(x)\right)
\right]
\tag{3.2}
$$

The expectation averages over the training observations. The parameters $\theta$ and $\phi$ are learned together: the encoder must produce features that help the classification head identify the rotation.

A useful reference point is uniform prediction. If the model assigns probability $1/4$ to every rotation, the loss for each example is

$$
-\log\frac14=\log 4\approx 1.386.
$$

The value is measured in nats, because we use the natural logarithm. A model that predicts the correct class confidently can achieve a lower loss.

Notice what we have done. We have not supplied the physics state $y$, the cart position, or the pole angle as a training label. The objective only asks the model to identify the applied rotation. Equation 3.2 is an ordinary four-class classification loss; the special feature is how its labels are generated.

#### Two other pretext tasks

Rotation prediction is one example of using structure in the input to create a target. Two other classic tasks take a different approach.

Jigsaw prediction divides an image into a grid of tiles, shuffles them using a permutation selected from a predefined set, and trains the model to identify that permutation. The spatial relationships between tiles supply the learning signal. This can encourage features that capture local appearance and spatial arrangement, but it does not directly require the model to preserve physical variables such as velocity.

Colorization takes a grayscale image and trains a model to predict its color channels. The target is derived from the original image, so human labeling is unnecessary. Predicting color can encourage the model to use contextual information, but good color reconstruction is not the same as learning a state suitable for control. The objective rewards information useful for recovering color; it does not explicitly require every geometric or dynamical distinction that a downstream world model may need.

#### Why a correct pretext answer may still be the wrong goal

Return to the principle from Section 3.1: the training objective determines what information the representation is required to keep. Rotation prediction rewards features that help identify the rotation label. If the scene layout or background already makes that label easy to infer, the objective may be solvable without preserving the pole angle with the precision that control requires.

The same distinction applies to the other tasks. Jigsaw prediction rewards information useful for identifying tile arrangement. Colorization rewards information useful for predicting colors. Each objective can encourage useful features, and a trained encoder may retain more information than strictly necessary to solve its pretext task. But none of these losses, by itself, guarantees that the representation is sufficient for predicting the physical future.

That is the limitation we need to solve. Rather than ask the encoder to predict one fixed transformation, we want a learning signal that encourages it to ignore irrelevant changes while preserving the distinctions that matter. Small shifts or brightness changes might be nuisance variation; different physical situations should not be made indistinguishable merely because their images look similar.

This leads to instance discrimination, the starting point for contrastive learning. We will make two altered views of an observation and ask the model to recognize them as views of the same source. The choice of alterations will matter: it defines which changes the objective encourages the encoder to ignore. In the next section, we will build this idea from first principles and derive the loss that implements it.
